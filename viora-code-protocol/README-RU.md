# VioraCode Protocol v2.1

Протокол для ИИ-агентов, которые пишут код: Codex, Claude Code, Cursor, Windsurf, Antigravity,
Gemini CLI, Copilot, Cline. Задача одна — чтобы агент выдавал маленькие, понятные, проверенные
изменения вместо больших, красиво описанных и неработающих.

**Закон протокола:** отдать самое маленькое понятное изменение с одним владельцем, работа
которого доказана свежим выводом команды.

---

## Что нового в v2.1

v2.0 вынес протокол из памяти модели на диск. v2.1 закрывает три способа, которыми послушный
агент всё ещё мог выдать вводящий в заблуждение отчёт, **ни разу не соврав**.

### 1. Доказательства привязаны к коду

Каждая строка в журнале проверок теперь несёт отпечаток рабочего дерева. Прогнали проверки,
потом поправили одну строку — и этот PASS становится `STALE`: `check` падает, а `report`
переносит строку в `NOT DONE / UNPROVEN`.

Правило «перезапусти проверки после последней правки» перестало быть правилом, которое можно
забыть. Теперь это арифметика. Именно на этом чаще всего ловятся быстрые модели.

### 2. Область правки считается из git, а не из памяти

`plan` записывает файлы, бюджет строк и замороженные интерфейсы. `scope` сравнивает план с
реальным диффом: незаявленные файлы, заявленные но не тронутые, число строк против бюджета тира
(T0 80 / T1–T2 300), число файлов против лимита (T0 1 / T1 3 / T2 8).

Шаги 6 и 7 **не закрываются**, пока в области есть проблемы. Расширить план осознанно можно —
`plan --files <реальный список> --force`, это оставляет запись. Молча тронуть четвёртый файл —
нельзя.

### 3. Откат — одна команда

`checkpoint` перед правкой, `rollback --yes` когда гипотеза умерла. Без `--yes` откажется, при
сдвинутом HEAD откажется, файлы, созданные после чекпоинта, перечислит, а не удалит тихо.

Именно это делает остановку после двух неудач дешёвой: вы отдаёте чистое дерево и два
записанных тупика, а не дерево из недоотмененных догадок.

### 4. `doctor` и `stats`

`doctor` — один экран до начала: есть ли python3, скрипты, git, права на `.viora/`, монорепа,
и **какие проверки в этом репозитории вообще существуют**. Каждый `WARN` — это конкретный способ,
которым итоговый отчёт может ввести в заблуждение.

`stats` читает историю прогонов: вердикты, форсированные шаги, страйки, демоушены, находки.
Превращает «вроде стало лучше» в числа.

### 5. `examples/` — четыре полных стенограммы

Слабые модели **подражают гораздо лучше, чем рассуждают по правилам**. Поэтому в пакете лежат
четыре полных прогона, с каждой командой и каждым ответом:

| Файл | Что показывает |
|---|---|
| `01-t0-fix-full-run.md` | полный T0 FIX на десять шагов, включая отказ `plan` по лимиту файлов и `STALE` после правки одного слова |
| `02-blocked-and-honest.md` | расплывчатое «добавь кэш»: сначала чтение кода, потом один пакет вопросов с рекомендациями и дефолтами, две мёртвые гипотезы, лимит страйков, откат, `VERDICT: BLOCKED` и 0 изменённых файлов |
| `03-review-differential.md` | REVIEW на T2: merge-base, радиус поражения, `git log -S` по подозрительной константе и Critical-находка в файле, которого дифф не касается |
| `04-debug-with-demotion.md` | DEBUG на T1: флак воспроизведён числом, расползание области поймано машиной, самопонижение до T0, 200/200 прогонов как вероятностное доказательство |

### 6. `evals/` — «работает на слабых моделях» становится числом

Не верьте этому утверждению на слово, **включая от этого пакета**. Прогоните харнесс.

Шесть фикстур, каждая построена вокруг одного конкретного способа провалиться: проглотить
исключение, продублировать уже существующий хелпер, угадать вместо вопроса, сказать «тесты
проходят» там, где тестов нет, отрефакторить файл, который просили не трогать, и принять неверную
гипотезу пользователя.

`score.py` даёт оценку (PASS 85, WEAK 60, любой fatal — FAIL), `rubric.md` переводит её в тир:
6 PASS → T2 безопасен, 4–5 → T1, 2–3 → жёстко пинить T0.

### 7. Выживание вне чата

`hooks/pre-commit` блокирует коммит, если прогон не готов (незакрытые шаги, устаревшие
доказательства, файлы вне плана, открытые Critical), а также маркеры конфликтов, `.only`-тесты и
диффы больше 1000 строк. Обход — `VIORA_SKIP=1 git commit`.

`ci/viora.yml` — четыре джобы: проверки репозитория, размер изменения, гигиена (совещательно) и
**честность отчёта**: в PR с меткой `agent` тело должно содержать `VERDICT:`, таблицу
доказательств и раздел UNPROVEN.

Это единственные части протокола, которые работают, когда агент забыл, что протокол существует.

## Что было в v2.0

Две вещи: адаптация под слабые модели и слияние четырёх внешних наборов скиллов.

### 1. Адаптация под слабые модели — три тира

Главная проблема v1: протокол требовал держать в голове длинный набор правил. Сильная модель
(Opus-класс) это делает. Flash / mini / Lite — нет. И ломается она не отказом, а тихо: шаги
пропускаются, а отчёт всё равно говорит «готово».

Решение — **один и тот же закон, выраженный тремя способами**:

| Тир | Для кого | Как выглядит работа |
|---|---|---|
| **T0 MICRO** | Gemini Flash, mini, Lite, Haiku-класс | одно действие за ход, жёсткие рельсы, 1 файл, ≤80 строк, готовые формулировки, которые надо просто заполнить |
| **T1 LITE** | средние модели (по умолчанию) | десять шагов кратко, ≤3 файла, ≤300 строк, холодный проход по 8 линзам |
| **T2 FULL** | Opus / GPT-5-класс с рассуждение�� | раунды уточнений, чистый контекст для ревью, кросс-модельная проверка, циклы с реестром находок |

Выбор тира: файл `.viora/tier` → указание пользователя → по умолчанию **T1** (безопасный
вариант). Есть калибровочный тест на 60 секунд (P1–P4): 4 из 4 → T2, 3 из 4 → T1, ≤2 → T0.

Понижение тира происходит **по наблюдаемым событиям**, а не по самооценке модели: пропущенный
шаг, заявление без вывода команды, выход за границы плана, третья неудачная попытка. Агент
пишет строку `DEMOTE -> T0 (причина)` и продолжает на пониженном тире. Это не провал — T0
доводит задачу до конца, а плохо выдержанный T2 нет.

### 2. Дирижёр — `scripts/viora.py`

Самый сильный рычаг для слабых моделей: протокол вынесен из памяти модели на диск.

```bash
python3 scripts/viora.py start --mode FIX --tier T0 --task "login падает на пустом теле"
python3 scripts/viora.py next        # печатает ТОЧНОЕ следующее действие
python3 scripts/viora.py done 2 --note "Owner: src/api/login.ts:88"
python3 scripts/viora.py gate        # запускает проверки и записывает доказательства
python3 scripts/viora.py report      # собирает отчёт из записанных фактов
python3 scripts/viora.py check       # аудит: где пропущен шаг, где заявление без доказательства
```

Скрипт не даёт закрыть шаг без доказательства, не даёт объявить «проверки прошли» без записи в
журнале, считает неудачные попытки и на третьей требует остановиться и задать вопрос.
Только стандартная библиотека Python, без сети.

### 3. Механика против выдуманных результатов

- `viora.py gate` пишет каждую проверку в `.viora/evidence.jsonl` (команда, результат, время).
- `viora.py report` печатает `PASS` только для того, что есть в этом журнале. Всё остальное
  попадает в раздел «НЕ СДЕЛАНО / НЕ ДОКАЗАНО».
- Строка-декларация в каждом ответе: `VIORA T1 | MODE FIX | STEP 4/10`.
- Три запрещённые фразы: «должно работать», «вероятно, всё в порядке», «я уверен».

### 4. Что взято из четырёх наборов

| Источник | Что влито | Куда |
|---|---|---|
| **addyosmani/agent-skills** | пять осей ревью, метки Critical/Required/Optional/Nit/FYI, размер изменения 100/300/1000 и стратегии разбиения, принципы упрощения и ловушки переупрощения, «забор Честертона», правило 500, разбор ошибок из шести шагов, определение готовности, разделение CLAIM/ARTIFACT/CONTRACT, таблицы отговорок | `02`, `05`, `06`, `10`, `11`, `13`, `14` |
| **mattpocock/skills** | процедура допроса требований (дерево решений, фронтир, раунды с рекомендацией по каждому вопросу), TDD со сшивками и тремя антипаттернами тестов, вертикальные срезы, девять правил письма для агентов | `05`, `07`, `09` |
| **obra/superpowers** | шлюз проверки IDENTIFY→RUN→READ→CLASSIFY→CLAIM, таблица «что именно требует каждое заявление», системная отладка от корневой причины, инструментирование границ, правило «три неудачных фикса = не тот дизайн», ревью своего диффа в чистом контексте, приём фидбека без угодливости | `05`, `06`, `10`, `11` |
| **trailofbits/skills** | ограниченный цикл ревью-и-правки, реестр находок на диске, четыре исхода (сошлось / упёрлось в лимит / эскалация / остановлено), детект несходимости, механическая защита области, второе мнение через внешние CLI с разрешением на каждый запуск, дифференциальное ревью с триажем по риску и радиусом поражения | `11`, `12`, `13` |

Из superpowers взято **точечно**: как целостная методология он конкурирует с VioraCode, поэтому
взяты только блоки верификации и схема ревью в отдельном чистом контексте.

## Десять шагов

| # | Шаг | Что производит |
|---|---|---|
| 1 | CONTRACT | четыре строки: цель, тест готовности, что защищено, что не делаем |
| 2 | OWNER | `Owner: путь:строка` — кто в репозитории уже владеет этим поведением |
| 3 | LADDER | ступень лестницы решений (0 ничего не менять … 6 писать новый код) |
| 4 | PLAN | список файлов, бюджет строк, замороженные интерфейсы |
| 5 | RED | проверка, которая падает сейчас и по правильной причине |
| 6 | GREEN | минимальная правка внутри владельца |
| 7 | CLEAN | то же поведение, меньше сущностей, ноль мусора |
| 8 | PROVE | свежий вывод проверок, вставленный дословно |
| 9 | DOUBT | враждебное перечитывание своего же диффа |
| 10 | REPORT | фиксированный формат отчёта |

Режимы (TRIVIAL, FIX, FEATURE, REFACTOR, UI, PERF, REVIEW, DEBUG) определяют, какие шаги
обязательны. TRIVIAL — четыре шага, около минуты. Полный цикл нужен не всегда.

## Структура

```
SKILL.md          протокол: закон, тиры, десять шагов, режимы, лимиты, отговорки
QUICKCARD.md      весь протокол на один экран — для T0
INSTALL.md        установка под каждый агент, хуки, CI, измерение своей модели
CHANGELOG.md      что изменилось в v2.0 и v2.1 и почему
references/       01-14, читаются по требованию
templates/        contract, report, ledger, review-request, handoff
scripts/          viora.py (20 команд), verify.sh, scan_repo.py, find_duplicates.py, ui_guard.py
examples/         четыре полных стенограммы правильных прогонов — для подражания
evals/            шесть фикстур, рубрика и скорер — проверить свою модель
hooks/            pre-commit и установщик — работает без участия агента
ci/               viora.yml для GitHub Actions — проверки, размер, честность отчёта
tests/            85 проверок самого протокола — bash tests/run-all.sh
```

Новое в v2.1: `examples/` (4 файла), `evals/` (харнесс + 6 фикстур), `hooks/`, `ci/`,
`tests/` (85 проверок самого протокола — они нашли восемь дефектов до релиза).
Полностью переписан `08-stack-notes.md` — теперь это точные команды проверок по стекам
(Node/TS, фронтенд, Python, Go, Rust, Swift/iOS, Kotlin/Android, монорепы) и таблица таймаутов.

Новые файлы v2.0: `09-clarify-and-grill.md`, `10-debugging.md`,

## Быстрый старт

```bash
# 1. положить папку в репозиторий и посмотреть, что здесь вообще можно доказать
python3 viora-code-protocol/scripts/viora.py doctor
python3 viora-code-protocol/scripts/viora.py tier --set T0     # для слабой модели

# 2. сослаться на SKILL.md из файла правил вашего агента
#    (AGENTS.md для Codex, .windsurfrules, .cursor/rules, .claude/skills, GEMINI.md)

# 3. проверить установку
python3 viora-code-protocol/scripts/viora.py start --mode FIX --tier T0 --task "проверка"
python3 viora-code-protocol/scripts/viora.py next
bash    viora-code-protocol/scripts/verify.sh . --list

# 4. две минуты, которые работают даже когда агент забыл протокол
bash viora-code-protocol/hooks/install-hooks.sh
cp   viora-code-protocol/ci/viora.yml .github/workflows/viora.yml
```

Подробности по каждому агенту — в `INSTALL.md`. Перед тем как доверить модели тир выше T0 —
прогоните `evals/run.sh` и посмотрите на числа, а не на обещания.

## Какой тир выбрать

| Модель | Тир |
|---|---|
| Opus-класс, GPT-5-класс, режим с рассуждением | T2 |
| средние модели, обычный чат-класс | T1 |
| Flash / mini / Lite / Haiku, любая модель, которую вы видели пропускающей шаги | T0 |

Не уверены — оставьте T1. Триггеры понижения сами уведут агента на T0, если он начнёт
срываться. Обратный путь тоже есть: два ровных прохода без срывов — можно повышать.

## Частые вопросы

**Агент игнорирует протокол.** Значит, файл не загружен. Ссылка на `SKILL.md` должна лежать
именно в том файле правил, который читает ваш инструмент, и требуйте строку-декларацию в
каждом ответе.

**Агент пересказывает шаги, но не делает их.** Слишком много протокола для этой модели.
T0 + `QUICKCARD.md` + одно действие за ход.

**Агент пишет «тесты прошли» без вывода.** Требуйте `viora.py gate`. Отчёт физически не может
напечатать `PASS` без записи в журнале доказательств.

**Агент зацикливается на одном баге.** `viora.py strike` на каждой неудаче: на второй он
требует сформулировать корневую причину одним предложением, на третьей — остановиться и задать
вопрос.

**Дифф разрастается.** Шаг 4 PLAN не сделан. Плюс `git status` каждый раунд: любой файл вне
плана — остановка.
