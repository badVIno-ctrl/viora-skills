# Viora Code Protocol - зачем это и как пользоваться

*Инженерный стандарт Viora Studio. Пара к Viora Design Skills.*

Один универсальный скилл для любого кодового агента. Он заменяет набор разрозненных инструкций и убирает главные причины плохого кода у ИИ-агентов.

## Какие проблемы он лечит

| Проблема | Что делает протокол |
|---|---|
| Агент пишет второй компонент/функцию вместо использования существующей | Фаза «Разведка»: обязательный поиск владельца концепта до написания кода + сканер дублей |
| Интерфейсы накладываются друг на друга, панели перекрывают и заменяют друг друга | Раздел «Целостность UI»: одна точка монтирования, один владелец поверхности, «замени, а не накладывай», единая шкала слоёв вместо z-index-войн |
| Большая нагрузка на устройство, утечки, лаги | Бюджеты производительности + список тяжёлых паттернов + парные «teardown» для каждого слушателя, таймера, подписки |
| Нерабочий код и заявления «готово» без проверки | Железный закон: нет свежего вывода команд - нет заявления о готовности. `verify.sh` собирает таблицу доказательств |
| Раздутые файлы и нечитаемость | Жёсткие числовые лимиты (файл ≤400 строк, функция ≤50, вложенность ≤3, параметры ≤4) |
| Мёртвый код и «сироты» | Всё созданное сразу подключается, всё заменённое - удаляется в том же изменении |

## Главное: работает и на слабых, и на сильных моделях

- **LITE** - для быстрых/небольших моделей: строгий чек-лист из 12 шагов, по одному шагу за раз, маленькие диффы, скрипты вместо интуиции.
- **FULL** - для сильных моделей: те же ворота плюс письменный контракт, карта владельцев, план файлов с зафиксированными интерфейсами и обзор по шести линзам.

Ворота (линт, типы, тесты, сборка, доказательства) одинаковы для обеих полос. LITE - это короткий путь, а не разрешение не проверять.

## Как установить

1. Скопируйте папку `viora-code-protocol/` туда, откуда ваш агент читает скиллы (папка скиллов пользователя или проекта).
2. Либо положите её в репозиторий и добавьте одну строку в файл инструкций проекта: «перед любым изменением кода читай и выполняй `./viora-code-protocol/SKILL.md`».
3. Если у агента есть только поле системного промпта - вставьте разделы 3, 5, 6, 7 из `SKILL.md` (это компактное ядро).

Подробно, со всеми вариантами и проверкой установки - в `INSTALL.md`.

## Как пользоваться

Просто скажите агенту:

> Сделай <задачу>. Работай по Viora Code Protocol.

Правильное поведение агента: сначала объявляет полосу и режим (`Lane: LITE | Mode: FEATURE`), ищет существующего владельца кода, называет выбранную ступень «лестницы решений», перечисляет файлы, и только потом пишет код. В конце - отчёт с таблицей доказательств.

Полезные фразы:
- «Режим FIX: сначала воспроизведи баг проверкой, которая падает» - чинить будут причину, а не симптом.
- «Режим UI» - включает проверки наложения интерфейсов и утечек.
- «Режим PERF» - требует замеров до и после.
- «Только отчёт, без изменений» - режим REVIEW.

## Что внутри

```
SKILL.md          главный файл: маршрутизация задач, чек-лист LITE, лимиты, ворота, отчёт
README-RU.md      этот файл
INSTALL.md        установка в любого агента + проверка, что скилл реально работает
references/       8 файлов глубины: разведка и переиспользование, дизайн и лимиты,
                  целостность UI, производительность, тесты и доказательства,
                  ревью и отчёт, полосы моделей, особенности стеков
templates/        рабочие заметки (контракт) и шаблон финального отчёта
scripts/          scan_repo.py, find_duplicates.py, ui_guard.py, verify.sh
```

## Скрипты (только чтение, без сети, только стандартная библиотека)

```bash
python3 scripts/scan_repo.py .            # стек, команды репозитория, точки входа, слишком большие файлы
python3 scripts/find_duplicates.py .      # клоны кода, одинаковые имена в разных файлах, повторяющиеся литералы
python3 scripts/ui_guard.py . --strict    # несколько точек монтирования, оверлеи, z-index, утечки, конфликты CSS
bash    scripts/verify.sh .               # запускает собственные проверки репозитория и печатает таблицу доказательств
```

Если Python или bash недоступны - в разделе 10 `SKILL.md` есть замены на чистом `grep`. Протокол работает и без скриптов, скрипты лишь ускоряют его.

## Настройка под свой проект

Меняйте только: числовые лимиты (раздел 5 `SKILL.md`), бюджеты производительности (раздел 1 в `references/04-...`), заметки по стеку (`references/08-...`) и команды в `scripts/verify.sh`. Ворота, лестницу решений, закон доказательств и формат отчёта лучше не трогать - именно они и держат качество.
