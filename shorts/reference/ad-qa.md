# QA рекламы и выпуск

Разделять: структура карточки -> технический файл -> редакторская проверка -> допуск оффера
-> разрешение на конкретный запуск. Ни один уровень не заменяет остальные.

## Ручные ворота

Сохранять в campaign.qa для каждого пункта {passed: true/false, evidence: "что/где проверено"}.
Не ставить true по инструкции или предположению. Ссылка на доказательство может быть
локальным отчётом/скриншотом с датой/условиями. Все неизвестные оставлять false.

| Ключ | Что проверить |
|---|---|
| product_action | Реальный продукт, аудитория, ясное целевое действие |
| claims | Все фразы/цены/скидки/выгоды имеют применимое подтверждение; нет выдуманных отзывов |
| rights | Видео/музыка/фото/логотип лицензированы для коммерческого применения |
| phone_readability | Реальный размер телефона, краткий текст и читаемая иерархия |
| overlay_clear | Весь интервал, не перекрыты лицо/товар/интерфейс/субтитры/UI |
| silent_comprehension | Понятно без звука, если это предусмотрено; для статичного макета - смысл изображения |
| subtitles | Слова/тайминг/переносы проверены, реклама не спорит за ту же зону |
| motion_audio | Полный финальный MP4 просмотрен и прослушан, не только контактный лист |
| cta_route | CTA соответствует реальной доступной точке перехода на выбранном аккаунте |
| landing | Ссылка/параметры/редиректы/посадочная/цена/язык/ГЕО совпадают с обещанием |
| disclosure | Проверены действующие правила страны/площадки, раскрытие выполнено |
| measurement | Событие, источник, ограничения атрибуции, окно, затраты и остановка определены |

Для статичного объявления разрешено исключить ТОЛЬКО motion_audio/subtitles:
`{applicability: "not_applicable", passed: false, evidence: "PNG без аудио и временных субтитров; файл проверен ..."}`.
Для применимого пункта applicability="applicable" либо отсутствует (старые карточки совместимы).
Неприменимость не равна успешной проверке: не ставить passed=true и не выдумывать прослушивание.
Для видео и остальных пунктов N/A запрещено. Сам текст изображения проверять в claims,
silent_comprehension и phone_readability; N/A не отменяет права/маршрут/раскрытие/согласование.
Для креатива без QR final_qr_verified в release не требуется; для QR проверить финальный MP4.
Для исключения пункта привести проверяемую причину, а не удалить пункт.

## Рекламный контроль

ad-check сохраняет ad-qa-draft.json / ad-qa-launch.json; ad-qa.json - последний результат.
ad-check draft: валидная структура, допустимые интервалы/геометрия; ready_for_launch=false всегда.
ad-check launch: продукт/аудитория/условия/допуск; claims/assets с evidence;
QA и ссылки на проверку; подтверждение пути; официальный источник правил с датой/областью;
план эксперимента и трекинг; полномочия/лимиты; SHA-256 существующего финального файла.
Все доказательства указываются агентом/человеком: код проверяет заполненность и согласованность,
НЕ делает юридическую экспертизу, не читает лицензии и не запускает браузер.

Указать final_artifact.path относительно campaign.json, SHA-256 файла после последнего рендера.
Никогда не ставить launch на учебном продукте. Не обходить ошибки через --stage draft.
Получить publication_approved и authorization.evidence для конкретного объёма/канала/срока.
Для paid_media=true требовать бюджет, валюту, max_loss, stop_method и spend_approved с evidence.
Нулевой бюджет не означает разрешение на платный запуск или платный API.

Для видео release.json содержит advertising=true; campaign.json лежит в том же каталоге.
release-check дополнительно выполняет рекламный контроль, а qa остаётся техническим.
Для статичного PNG/SVG достаточно ad-check launch плюс ручной визуальный QA файла;
не создавать фиктивные release.json/MP4, чтобы «пройти» видеопроверку.

## Приёмка креатива

Видно обещание -> показано действие -> дан полезный результат -> понятен один переход.
Если один из элементов отсутствует, исправить смысл, не только оформление.
Если нет средств рендера, передать точное ТЗ; если нет просмотра/слуха/доступа к площадке,
выдать превью и список незакрытых пунктов. Не называть «готово к запуску» по зелёному lint.
Подтверждённый технический выпуск не прогнозирует охват, конверсии или прибыль.

## Что добавлено в 1.7.0 (ad-check launch)
Новые блокирующие проверки: `reviewer` (человек, не равен `author`, дата и заявление), свежесть дат
(offer.checked_at, rules, evidence утверждений и прав, reviewer.confirmed_at; по умолчанию 30 дней,
`evidence_max_age_days` 1..90, `--today` для проверки на дату), `disclosure` для affiliate/fixed_placement,
минимум 2 варианта с разными concept и гипотезой, per-creative механизм в tracking.method при attribution_level=creative,
некликабельное место ссылки на YouTube Shorts, рискованные формулировки без подтверждённого утверждения
(`claims[].covers`), запрещённые обещания гарантированного дохода и выдуманных экспертов, персональные данные в URL,
азартные игры как заработок, возрастные офферы. Для drafts это предупреждения.
Длина текстов (заголовок 3-7 слов, CTA 2-4 слова) только предупреждение [Г].
Линтер текстов эвристический: «чисто» не доказывает честность формулировки; решает человек-проверяющий.

Баннер: `ad-render` пишет banner-report.json. Это арифметика макета (контраст WCAG, переполнение, 14 px при ширине 360,
safe-зоны), а не смысловая и юридическая проверка. Файлы цветной, монохромный и превью 360 px открыть глазами,
результат записать в qa.phone_readability с доказательством.
