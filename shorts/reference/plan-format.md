# Формат плана (schema v1, 1.1, 1.2, 1.3, 1.4)

Полная схема: `schema/plan.schema.json`. Пример: `schema/plan.example.json`, офлайн-пример: `tests/fixtures/plan.offline.json`.

## Сцена
```json
{"id": "site-1", "say": "Как читает голос", "on_screen_text": "2-4 СЛОВА", "why": "зачем эта сцена",
 "duration": 4.0, "source": {"type": "site", "ref": "https://...", "actions": [...]},
 "speed": [{"t": 3, "rate": 1.5}], "sfx": [{"t": 0, "name": "click"}]}
```
- Длина сцены = длина озвучки `say` + 0.35 с (или `duration`, если голоса нет; берётся большее).
- `speed`: `t` в секундах исходника от начала сцены, `rate` 0.25-4 (1.5-3 скучное, 0.3-0.6 ключевой момент).
- `sfx`: имя реальной записи `assets/audio/sfx/<имя>.wav|mp3|ogg|flac` (2.2: без файла событие выбрасывается,
  синтезированных тонов нет; `audio.sfx`: files | off | synth, см. `reference/audio.md`). `audio.sfx_auto` (свуш на смену
  сцены, щелчок на клик, поп на CTA) по умолчанию выключен.
- `transcript`: тайминги слов живой речи в сцене (для субтитров без `say`).

## Действия на сайте (`source.actions`)
| do | поля | что делает |
|---|---|---|
| `goto` | `url`, `settle` | открывает страницу (первое действие, добавляется само), проверяет защиту |
| `click` | `text` / `role`+`name` / `label` / `placeholder` / `sel` | курсор едет к элементу, кольцо клика, камера зумит |
| `hover` | то же | наведение |
| `type` | селектор + `text`, `delay` | клик в поле и печать |
| `press` | `key` | клавиша (Enter) |
| `scroll` | `dy`, `steps`, `at` | плавная прокрутка |
| `wait` | `s` | пауза |
| `dismiss_cookies` | - | закрывает баннер cookies, если есть |
Поле `t` (секунды от загрузки) ставит действие на таймлайн; без `t` действия идут подряд с паузой `after`.
`required: true` = ошибка, если действие не вышло (иначе пропуск с пометкой в отчёте).
Порядок локаторов: `role` > `label` > `text` > `sel` (CSS, когда ничего другого нет).
`viewport`: `mobile` (по умолчанию, 540 CSS px, чётко на 1080), `desktop`, или `{"w": 800}`.

## Вспышки CTA (`layout.cta_in_center`, до 3)
`{"t": 14, "duration": 2.5, "kind": "handle", "text": "ник"}`, `{"kind": "qr", "url": "https://..."}`,
`{"kind": "text", "text": "часть 2 в канале"}`. Время за пределами ролика сдвигается в конец.

## Эффекты для эдитов (`fx`)
`{"punch": [t...], "flash": [t...]}`: зум-удар 0.3 с и вспышка 2 кадра на сильных долях.

## Поля 1.3 (монтаж и подача, все необязательные)
Подробно, с примерами и правилами: `reference/vfx.md`. Готовые планы: `examples/e-*.plan.json` ... `h-*.plan.json`.

| Поле | Что |
|---|---|
| `layout.top.source: "bg:auto"` / `"bg:<id>"`, `layout.top.fit`, `layout.top.start` | баннер из геймплея (библиотека `assets/footage/library.json`) |
| `layout.split[]` | второе окно: `v2`, `h2`, `pip`; `b` = `bg:...` или файл |
| `layout.mode: "band"`, `band_h`, `band_y`, `layout.title_bar` | полоса "кинобаст" и плашка темы |
| `layout.cta_in_center[].kind: "subscribe"`, `target` | карточка канала, курсор жмёт "подписаться" |
| `captions.style: "kinetic"`, `captions.kinetic` | фраза строится по словам в столбик |
| `overlays.facts[]`, `overlays.arrow` | плашки фактов в нижней трети, стрелка к ссылке в конце |
| `overlays.post` | карточка поста (reddit / telegram / comment), текст дописывается под голос (раскладка C) |
| `scenes[].source.ref: "bg:auto"` (`video`) | геймплей из библиотеки фона на весь кадр (раскладка C) |
| `fx.letterbox`, `fx.flicker`, `fx.look_keys`, `fx.transitions` | полосы кино, мерцание, смена цвета, авто-переходы |
| `scenes[].trans` | переход в сцену: `whip`, `zoom`, `flash_blur`, `glitch`, `dip`, `spin`, `dissolve`, `flicker` |
| `audio.export` | `both` = ещё файл без музыки + `music_cue.json` |
| `author_layer[]` | свой вклад поверх чужого материала (минимум 2 слоя, один из `voice` / `thesis` / `own_footage` / `compare`) |

Время в этих полях: секунды, отрицательные от конца, `"drop"`, `"start"`, `"end"`, `"NN%"`.
Синонимы: `layout.title` -> `layout.title_bar`, `edit.look_keys` -> `fx.look_keys`.

## Core question и вау-тест 2.0 (ручная проверка агента)
Перед монтажом запиши одно напряжение ролика (core question) одной фразой: тайна, конфликт,
страх или изменение. Одна идея. Название - словесное обещание, обложка - визуальное,
хук - быстрое подтверждение, вступление - раскрытие того же обещания. Это заметка агента,
не новое обязательное поле JSON-схемы. Не заставляй пользователя заполнять план.

P0 обязательны, без провалов: кадр 0 останавливает без звука; тема понятна за секунду;
одна идея; первые 0-5 с подтверждают клик; хук не ломает обещание названия и обложки;
обещанное реально есть, факты проверены. Любой «нет» или «не проверено» - исправить до выдачи.

P1/P2: 12 критериев по одному баллу (да = 1, нет/неизвестно = 0):
P1: 1) есть новый угол; 2) отличие от изученных примеров можно назвать;
3) сильный момент на месте по формату; 4) обещание выполнено;
5) нет кусков без смысла, полезное развитие после раннего ответа сохраняется; 6) звук/текст читаемы и технический QA пройден;
7) одна понятная эмоция; 8) музыка и вид её поддерживают.
P2: 9) есть момент для пересылки; 10) понятно, кому и зачем его переслать;
11) есть свой тезис/голос/сравнение; 12) авторский вклад меняет смысл, а не только оформление.
Для своего материала 11-12 оценивают авторскую точку зрения; для чужого дополнительно обязателен
контракт минимум двух слоёв из schema 1.3, один ключевой.

Все P0 + минимум 9 из 12: готово по творческому тесту; 6-8 - исправить слабое; меньше 6 -
вернуться к концепции. На стадии плана QA пока не проверен, итоговый балл пересчитай после сборки.
В research/traffic-v3.1/00 исходная шкала - 6 пунктов по 0-2 (12 баллов), здесь каждый разбит
на два проверяемых признака, чтобы выполнить формат 12 критериев. Это адаптация скилла,
не дословная шкала автора. Порог некалиброванный: ориентир, проверяется на ваших цифрах.
Запиши ответы и основания в out/<имя>/wow-review.md, балл в memory/metrics.md; через 30 роликов
проверь связь с результатом. Вау-балл не равен техническому QA и не гарантирует просмотры.

CTA: лайк коротко на эмоциональном пике в середине (данные JRIM, одна англоязычная выборка),
подписка - конкретным обещанием следующего ролика серии. Просьба «подпишись» допустима,
но не основная механика. Один главный целевой шаг по цели бренда, не набор просьб.

## Тейки: от сырья до плана


13. ПРОТОКОЛ ТЕЙКОВ v3.2 [Г, рабочая процедура]
====================================================================
 Тейк - отдельный дубль или ограниченный фрагмент источника. Нарезка готового MP4
 тоже получает карточки по смысловым кускам; это не обязательно исходные дубли съёмки.
 1. Составь реестр ВСЕХ доступных тейков. ID, файл, in/out в секундах исходника,
    группа сцены и альтернативный дубль. Границы включают начало и исключают конец.
 2. Для каждого отдельно открой доступное изображение и прослушай звук. Статусы
    независимы: изображение просмотрено / выборка кадров / не просмотрено;
    звук прослушан / технически декодирован / не прослушан.
    Не называй расшифровку прослушиванием, контактный лист просмотром движения.
 3. Карточка (каждое поле обязательно; неизвестно допустимо):
    ID; файл; in/out; группа дублей; статус изображения и звука; что реально
    увидено; что реально услышано; роль в истории;
    содержание: сила / дефект; подача: сила / дефект;
    картинка: сила / дефект; звук: сила / дефект;
    дефект с таймкодом (фальшь, оговорка, шум, брак, вода либо не обнаружено);
    вердикт: оставить / сократить / переставить / исправить / заменить / доснять /
    исключить; конкретная обработка; место в итоговой шкале; ID итоговой сцены.
 4. Сравни альтернативные дубли одной сцены бок о бок: содержание, подача, картинка,
    звук и цена исправления, а не единый скрытый балл. Выбери лучший под роль.
    Не склеивай все дубли. Если нужна комбинация - укажи точные границы и причину.
    Не требуется использовать каждый тейк. Исключить - нормальное решение.
 5. Собери таблицу: ID сцены | ID тейка | source.in/out | длительность выхода |
    место выхода | обработка | зачем. В коротком плане source.ref/in/out и duration
    соответствуют таблице; карточки хранятся рядом в takes.md, не в новой памяти.
    В длинном плане schema 1.4: video.format=long, правила reference/long-videos.md.
 6. Проверь стыки: слова не обрезаны, паузы осмысленны, нет случайного повтора,
    не потерян контекст, совпадают направление движения, звук и громкость.
    Затем весь ролик: название -> обложка -> хук -> реальная отдача.
 7. Если восприятие недоступно - запиши ограничение и отложи соответствующий вердикт.
    Экспорт и авто-QA этого не устраняют. После сборки просмотри движение и звук;
    недоступный ручной просмотр оставляет приёмку частичной.
 8. Вход слабый MP4: сохрани оригинал и его hash; разбей по фрагментам, проверь оба
    канала восприятия, запиши старую и новую шкалы; экспортируй НОВЫЙ файл.
    Покажи измеримые изменения (границы, порядок, удалённые куски, звук), а не
    выдуманные карточки. Учебный файл обозначь учебным и приложи генератор.

Карточки не заменяют реальную обработку. Матрица приёмки: `acceptance/REPORT.md`.

## Поля 1.4

video.format=long: отдельный профиль `reference/long-videos.md`.
Для новых коротких: meta.pacing=meaning оставляет ритм ручной проверкой по жанру;
meta.loop=false разрешает законченное завершение без петли. В старых планах значения
по умолчанию и проверки не меняются. Не ставь meaning только чтобы обойти ошибку:
объясни в brief.md, какую демонстрацию/паузу нельзя прерывать, проверь весь ролик.

Schema 1.4: meta.genre задаёт жанр (edit/tutorial/interview/story/observation/other).
Проверки разнообразия шотов и запрета титров кино-эдита не применяются к явно
выбранному другому жанру. Это не отключает технические проверки кадра и текста.
Для старых планов поведение прежнее. Не меняй жанр ради обхода реального дефекта.

## Рекламная карточка v3.4
campaign.json - отдельная спецификация по schema/campaign.schema.json, НЕ поле plan.json.
Она не меняет монтаж и не передаётся render. Скопировать карточку в выходной каталог видео,
заполнить release.advertising=true, пройти ad-check и release-check.
Интервалы/геометрию campaign перенести в поддерживаемые поля монтажного плана или отдельный
монтажный инструмент; затем проверить фактический файл. Не выдумывать неподдерживаемые поля.
