## 1. Данные и определения

До публикации согласовать точное событие/источник: просмотр видео, открытие профиля,
клик по партнёрской ссылке и подтверждённая продажа - разные события.
Сохранять период, часовой пояс, площадку, источник трафика, ГЕО, вариант, окно атрибуции,
числители/знаменатели и валюту. Пропуск = неизвестно, не ноль.
Отдельно показывать начислено, подтверждено, фактически выплачено; pending не включать
в завершённую проверку. Учитывать возвраты, холд и задержки, не смешивать несопоставимые когорты.

## 2. Метрики

| Метрика | Расчёт |
|---|---|
| Переходы из видео | Точное событие перехода / сопоставимые просмотры |
| CTR объявления | Клики / показы * 100% |
| CR этапа | Целевые действия / соответствующие клики * 100% |
| Апрув | Подтверждённые / (подтверждённые + отклонённые) * 100% |
| EPC | Подтверждённое вознаграждение / соответствующие клики (за ОДИН клик, как в PDF). У Admitad Academy EPC = заработок на 100 кликов: при сравнении с карточкой оффера назвать определение; ad-metrics выдаёт epc и epc_per_100_clicks |
| Цена подтверждённого действия | Все учтённые расходы / подтверждённые действия |
| Прибыль | Подтверждённое вознаграждение - все учтённые расходы |
| ROI | Прибыль / расходы * 100%, только при расходах >0 |

При нуле знаменателя доля не определена, не 0% и не бесконечная окупаемость.
В расходы включить закупку трафика, производство, API/подписки, комиссии и стоимость времени;
налоги/прочие исключения явно назвать. Не сравнивать EPC только с ценой рекламного клика.
У прямого продавца использовать согласованную маржинальную модель, не CPA-выплату из воздуха.

Учебный расчёт [Г]: 20 000 просмотров, 200 партнёрских кликов, 10 заявок,
6 подтверждены, 4 отклонены, 500 RUB/подтверждение, расходы 1 200 RUB.
Вознаграждение 3 000 RUB, CR заявок 5%, апрув 60%, EPC 15 RUB,
цена подтверждения 200 RUB, прибыль 1 800 RUB, ROI 150% до неучтённых затрат/налогов.
Это не прогноз и не рыночная норма; выплаченная сумма неизвестна без платёжного отчёта.
Расчёт воспроизводится командой: `python tools/shorts.py ad-metrics templates/advertising/metrics.example.json`.

### ad-metrics (1.7.0)
Вход: JSON с числами пользователя (views, link_clicks, actions, confirmed, rejected, pending, payout_per_action,
spend_total или spend по статьям; необязательно variants[], limits{spend_limit,max_loss,min_clicks,min_actions,window_days,elapsed_days},
flags{rule_violation,wrong_link,offer_mismatch}). Ничего не запрашивается и не оценивается; нули в знаменателе дают null.
Выход: метрики, 95% интервалы Уилсона, статус `preliminary` (пока есть pending, не закончен холд или нет выплаты) / `final`,
диагностика воронки и решение: STOP (флаг нарушения, превышение заранее заданного лимита), INSUFFICIENT_DATA
(<100 кликов, <10 подтверждений, <7 дней: пороги [Г], не нормы рынка), HOLD, REPEAT, REVISE_OR_STOP.
Варианты органических постов сравнивать как квази-эксперимент: разные аудитории и охват, не рандомизированный A/B.
`--log DIR` дописывает запись в experiments.jsonl (журнал только добавляется).

## 3. Атрибуция

UTM - для веб-аналитики; поддерживаемые сетью SubID/click ID - для партнёрских конверсий.
UTM сами по себе НЕ доказывают партнёрскую атрибуцию. Не добавлять параметры
к подписанной ссылке вслепую; использовать генератор/документацию программы.
Не передавать имена, email, телефоны и другие персональные данные зрителей в UTM/SubID.

Если все ролики ведут в одну ссылку профиля, а ID ролика не передаётся, отчитываться
на уровне канала/периода. Для разделения предложить разрешённые уникальные страницы,
коды или непересекающиеся тестовые периоды с оговорками; не обещать точность до продажи
конкретного шортса. Записать campaign.tracking.attribution_level и limitations.

## 4. Эксперимент

До запуска заполнить templates/advertising/experiment.md:
гипотеза/варианты/контроль, главная метрика и источник, единое окно/когорта,
затраты/валюта/бюджет/предел убытка, лимиты API, стоп-условие и дата решения с учётом холда.
Начать с доступного пакета (например 6-10 роликов [Г]); это план производства,
не статистическая достаточность. Не обещать доход за 4-5 дней и не выделять треть бюджета
как универсальную норму. Объём и окно выбирать по ресурсам/событиям/задержкам.

Для причинной гипотезы менять один фактор: сообщение, CTA, момент оверлея или визуал.
Разные концепции сначала сравнивать пакетами, не приписывая эффект одному элементу.
Для влияния оверлея на удержание добавить контроль без рекламы/с прежним оформлением.
Органические публикации получают разную аудиторию: квазиэксперимент, не рандомизированный A/B.
Записать размер выборки, неопределённость, исключения и выбросы; один вирусный ролик
или ноль продаж на малом числе кликов не устанавливает закономерность.

Остановить немедленно при неверной ссылке, несоответствии оффера/ГЕО, нарушении правил
и превышении согласованного лимита. По экономике учитывать pending/возвраты/холд;
не продолжать расход «пока всё подтвердится» за пределом согласованного убытка.
Масштабировать после повторяемых результатов и подтверждённых выплат.

## 5. Диагностика

| Симптом | Сначала проверить |
|---|---|
| Нет просмотров | Тема/хук/оригинальность/качество/ограничения; не ставить «теневой бан» без данных |
| Просмотры есть, переходов нет | Соответствие продукта аудитории, заметность CTA, доступность ссылки |
| Клики есть, действий нет | Посадочная, язык/ГЕО, цена, ошибки, совпадение с обещанием |
| Лиды есть, низкий апрув | Источник/допуск, ГЕО, дубли, правила и качество лидов |
| Действия есть, прибыли нет | Подтверждённая выплата, возвраты, полные расходы/комиссии |
| Удержание падает на оверлее | Размер/время/читаемость, конфликт с содержанием/субтитрами |

Активное долгое объявление в spy доказывает размещение, не прибыль. AffTrends использовать
для кандидатов/идей/гипотез, не для гарантии надёжности и дохода по рейтингу или ставке «до».
