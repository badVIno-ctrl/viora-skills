# Получение источников: ограниченно, настойчиво, без подмены

Проверить URL, название, автора, выпуск, человека, сцену и версию трека.
Если подпись и href различаются, проверить обе; не предпочитать href автоматически.

Порядок: штатная загрузка -> доступное воспроизведение/запись фрагмента -> поиск
официальной публикации/открытой идентичной копии на другой площадке -> сверка содержания
и качества -> журнал. Одна ошибка загрузчика не означает отсутствие материала.
Не повторять одинаковую ошибку без новых оснований. Бюджет движка: до 6 попыток методов,
не более одного метода на каждый URL за проход. Новые кандидаты сначала проверять.

`adapters/media.download_section` использует `recovery.resolve`, пишет JSON в
`$SHORTS_CACHE/source-journal`. Лучшие открытые копии передать через JSON-реестр
`SHORTS_SOURCE_REGISTRY`: ключ - исходный URL, значение - title и copies.
Для копии нужны url, relation=same_material, identity_verified=true,
identity_evidence (человек/выпуск/сцена/реплика/аудиоверсия), quality_usable.
Не ставить true по совпадению одного заголовка. Записать проверенную основу решения.

Автоматический поиск возвращает **непроверенных кандидатов**, не заменяет исходник.
Не удалось получить проверенную копию - изучить журнал и кандидатов, выполнить агентский
поиск по другим площадкам, сверить содержание. Автоматический поиск не исчерпывает интернет.
При отсутствии доказательств остановить только зависимую часть и назвать пробел.

Состояния: downloader_failed, playback_failed, no_verified_copy,
authorization_required, quality_unusable, identity_unverified. Нужна авторизация -
отдельный безопасный запрос владельцу. Похожая игра/музыка - replacement, не same_material.
Существенную замену согласовать **до** выдачи. Не создавать иллюзию точного выполнения.
