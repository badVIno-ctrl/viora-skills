# Из сырья в сильный ролик

Источник: исследование автора, метки в research/traffic-v3.1 (файл 26; шкала 00, критика 24).
Читай при слабом старом ролике, длинной записи, разрозненных заметках или просьбе «сделай вау».

1. Определи вход: заметки, сырая запись, готовый слабый ролик, чужой материал или только тема.
   Для опубликованного ролика выбери режим: пересборка либо гипотеза (reference/growth-loop.md).
   Не делай полный перемонтаж ради низкого CTR при хорошем досмотре.
2. Найди 1-5 реальных сильных моментов с таймкодами: эмоция, проверенный факт, конфликт,
   контраст, визуальная аномалия. Тест: какие 10 секунд стоило бы оставить? Не выдумывай факты.
   Нет сильного момента - попроси другой материал или предложи сменить тему, эффекты не спасут.
3. Одна идея и core question: одно напряжение, которое разрешает ролик. Название, обложка,
   хук и вступление дают одно обещание. Несколько самостоятельных тем - возможная серия; длинное может содержать несколько сильных эпизодов общей темы.
4. Агент решает по каждому фрагменту: сохранить, вырезать, переставить, заменить или добавить
   свой комментарий. Слабое вступление убрать; контекст оставить только необходимый.
   Для ремонта по цифрам меняй лишь выбранный шаг; полный трансформер - отдельная пересборка,
   не эксперимент с одной переменной.
5. До монтажа придумай 5-7 финальных названий и три разные идеи обложки. Проверь обещание
   в первые 0-5 с и читаемость обложки на 150 px. Хук не переключает тему.
6. Сильный момент по формату: эдит - дроп, история - развязка, список - лучший пункт ближе к концу.
   Убирай куски без новой мысли или эмоции. Голос громче музыки; в речевом формате голос сразу,
   в безголосом подтверждение делает изображение. Финал завершает мысль; петля или мост нужны только по задаче.
7. Чужое сырьё: соблюдай текущий контракт validate/QA - минимум два авторских слоя, один ключевой.
   Допущение исследования «один сильный» не отменяет schema 1.3.
8. До рендера и после него проведи вау-тест из reference/plan-format.md, затем validate, render,
   qa и реальный просмотр кадров/review. Запиши оценку с причинами, не называй её авто-QA.
   После публикации - один эксперимент на три ролика, потом замер. Успех не обещай.

## До поиска золота

Пройди протокол тейков из reference/plan-format.md (канон: файл 26, раздел 13).
Оцени каждый дубль отдельно, сравни альтернативы, исключи ненужное.
Пересборка может менять всё сразу; правило одного изменения только для гипотезы.
