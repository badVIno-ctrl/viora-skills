# Рабочий процесс 2.1: пошагово, без догадок

Для любой модели. Идти по шагам по порядку. Каждый шаг заканчивается проверкой с конкретным числом. Нет проверки - шаг не закончен.
Команды: `python tools/shorts.py КОМАНДА`. Заготовки JSON: `templates/recipes/`.

## 0. Перед стартом (2 минуты)
1. Реклама VPN: в РФ с 01.09.2025 реклама VPN и ссылок на VPN-боты запрещена. Скажи об этом человеку одной строкой в отчёте. Собрать ролик можно, публикацию не предлагать.
2. Права на исходники и музыку: записать источник и автора каждого куска (`credits` в `pack.json`).
3. Нужны: `ffmpeg`, `python -m pip install -r requirements.txt`. Проверка: `python tools/shorts.py doctor`.

## 1. Исходники
`fetch URL --section С-С --out sources` скачивает только нужный отрезок. Результат всегда H.264 (WebM/AV1 перекодируется).
Проверка: `ffprobe` показывает h264 и звук, а `motion файл.mp4` даёт `ok: true` и пустой `freezes`. Куски `main.pieces` брать вне замираний. Исходники, скачанные вручную `yt-dlp --download-sections` без `--force-keyframes-at-cuts`, могут начинаться с замершего кадра на несколько секунд при идущем звуке: использовать только `fetch`. Не вышло: см. `reference/youtube-access.md`, остальные части работы продолжать.

## 2. Субтитры
`srt URL --start С --end С --out sources/x.srt` берёт YouTube-субтитры нужного отрезка (0 = начало отрезка). Повторяющиеся строки склеиваются.
Мат и значки автосубтитров (`[ __ ]`, `[Музыка]`) `srt` и `stack` убирают сами (`captions.mask: false` отключает маскировку). Нет субтитров у видео: словные тайминги из аудио по `reference/captions.md`. Проверка: время последней строки не больше длины куска.

## 3. Интервью или стендап → шортс (`stack`)
1. Копия `templates/recipes/interview-top-ad.json` (сверху видео) или `jokes-ad.json` (без верхней панели).
2. Заполнить: куски `main.pieces` (по 4-10 с, смена плана не реже чем раз в 3-6 с), `captions.srt`, `hook`, `adbar`.
3. Предпросмотр плашки: `adbar spec.json --out bar.png`. Должно быть `qr_ok: true`.
4. `stack spec.json`. Частота кадров выбирается сама (24/25/30; 50 и 60 делятся пополам). Не задавать `fps` вручную без причины.
5. Главный план занимает вертикальный кадр, а не узкую полосу: `main.h` не меньше 1000 px при верхней панели 560 и не меньше 1300 без плашки.
Проверка: `motion video.mp4` - `ok: true`, доля повторных кадров в каждой панели ниже 3%, замираний нет. Плашка: QR декодируется (`adbar_qr: true` в выводе `stack`).

## 4. Кино-эдит («Брат», «Слово пацана» и подобные)
Структура: 1) сильная реплика героя 3-6 с в начале; 2) нарезка планов 0.4-1.2 с по ударам музыки; 3) последний план держать 1.5-2 с.
Без рекламных панелей: `main.y=0`, `main.h=1920`. Сначала `fetch` кусков, затем `beats` по музыке (`reference/editorial-edit.md`), затем `stack`.
Команда: `edit --video ФАЙЛ_ИЛИ_URL --music ТРЕК --line-at А-Б --line-text "реплика" --look film -o plan.json`, затем `all plan.json --out папка`. Файл `-o` это план, не папка.
Проверка: в `plan.json` у всех сцен `shot-*` разные пары (`source.ref`, `source.in`). Если в логе «only N good frames for M shots», взять исходник длиннее (минуты, а не 60 с): при нехватке кадров повторы идут из других моментов, но кадров всё равно мало. `motion` готового файла: `ok: true`.
Лицензия: фильмы и музыка чужие. Выдавать как черновик для автора, отметить в `credits`, публикацию не предлагать.

## 5. Обложки: три разных
`covers video.mp4 --text "A" --text "B" --text "C" --t0 С --t1 С --tag @канал --out covers/`
Варианты A (крупное лицо), B (контекст), C (постер) берутся из разных кадров. Вывод `problems` должен быть пустым. Если нет - другие `--t0/--t1` или другие тексты.
Текст обложки: до 4 слов, контрастный, не ниже y=288 и не выше y=1248 (`reference/cover-packaging.md`).

## 6. Упаковка
`pack pack.json --out ГОТОВО --zip`: видео, 5-7 названий, 3 описания (громкое/среднее/спокойное), 3 обложки. Любое предупреждение пересказать человеку.
Проверка: `ГОТОВО/` содержит mp4, названия, описания и три обложки; mp4 1080x1920, до 180 с.

## 7. Причины лагов и что делать
| Симптом | Причина | Решение |
|---|---|---|
| Рывки панели при плавном движении | 60→25 кадров неравномерно | дать `stack` выбрать fps; не конвертировать вручную |
| Кроп «ступеньками» | положение лица обновлялось не каждый кадр | `main.track`: `group`, `biggest` или `center`; `stack` строит путь заранее |
| Битрейт ниже 4 Мбит/с | пережатый превью-файл | собирать из исходника, не из превью |
| `motion` показывает повторы | дубли кадров в исходнике | взять другой кусок или fps исходника |
| OpenCV не открывает файл | AV1/WebM | `fetch` перекодирует в H.264; вручную `ffmpeg -c:v libx264` |

## 8. Что не заявлять
Слабая и сильная модель проходят одни и те же шаги, но для слабых моделей этот процесс проверен только тестами кода, а не прогонами. Не писать «гарантированно», пока нет записанного прогона.
