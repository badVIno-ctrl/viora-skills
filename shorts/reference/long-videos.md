# Длинное видео: сценарий, сборка, экспорт и QA

## 2.3: длинный рисованный ролик (toon, 16:9)
Анимационная история или объяснялка на 3-15 минут без исходников: `toon-new DIR -t long` (16:9, главы, концовка).
- Структура: холодный старт до 8 с (самый сильный момент) -> карточка главы -> главы по 60-120 с -> концовка `endscreen` 12 с.
- Глава: `"chapter": {"num": 2, "text": "Ночь"}` на первой сцене главы; карточка на весь кадр (`chapter_card: "full"`) или
  угловая (`"corner"`). `toon-render` пишет `build/chapters.txt` (00:00 вступление, главы короче 10 с сливаются): вставить в описание.
- Удержание: повторный крючок каждые 30-45 с (вопрос, штамп, схема, новая глава), сцена не длиннее 12 с, новый ракурс
  каждые 3-6 с. `toon-check` для `format: "long"` проверяет всё это сам.
- Концовка: последняя сцена `"endscreen": true`, `dur` 12 (5-20 с под конечные заставки YouTube), без часов и плашек.
- Время рендера: ~3 мин на минуту ролика 1920x1080 (2 CPU, `--workers 2`); сначала `--draft`.
- Из длинного можно нарезать шортсы: те же сцены в `aspect: "9:16"` (герой и схемы перекомпонуются сами), не обрезать 16:9.
Подробно: `reference/toon.md`. Ниже прежний путь для длинного видео из исходников (schema 1.4).

## Поддержанный профиль (версия движка 1.5.0, schema 1.4)

Публичные render / qa / all сохранены. Для длинного укажи:

```json
{"schema_version":"1.4", "video":{"format":"long","width":1280,"height":720,"fit":"contain"},
 "meta":{"name":"lesson","language":"ru","platforms":["youtube"],"fps":30,"loop":false},
 "layout":{"mode":"center_only"},"brand":{"preset":"mono"},"captions":{"enabled":false},
 "audio":{"target_lufs":-14,"sfx_auto":false},
 "scenes":[{"id":"result","why":"выполнить обещание","source":{"type":"video","ref":"source.mp4","in":0,"out":120,"keep_audio":true},"duration":120}]}
```

Это пример структуры, source.mp4 нужно предоставить. Планы реальной учебной проверки:
`acceptance/fixture/long.plan.json`, генератор `acceptance/make_fixture.py`.

- Размер 1280x720 или 1920x1080, 30/60 fps; длина не ограничена коротким QA.
- Локальные video/film: явные in/out, нормальная скорость, без зацикливания или
  незаметного стоп-кадра при нехватке источника. Ошибка вместо выдуманной картинки.
- images: одно изображение на сцену; text: текстовая карточка. Разбивай большие карточки.
- Склейки по границам сцен; contain сохраняет кадр, cover осознанно обрезает.
- Звук исходника либо narration (локальный аудиофайл) либо say (доступный TTS).
  narration и say вместе запрещены; narration заменяет звук сцены, не накладывается.
  Если озвучка длиннее сцены, увеличь duration и исходный материал.
- on_screen_text: простая верхняя подпись. transcript или TTS words -> SRT рядом с MP4,
  без вжигания. Локальная озвучка без transcript не даёт распознанных субтитров.
- Музыку, шумоподавление, сложные эффекты подготовь в исходнике или narration.
  Смена скорости, fx, overlays, site/html, split и продвинутая анимация пока [ТЗ]
  для длинного пути. Валидатор отклоняет их, не молча пропускает.
- brand - совместимое поле контракта; длинный путь пока имеет фиксированный спокойный
  текстовый стиль, не переносит визуальные настройки короткого движка.
- Итог: MP4 H.264/AAC, manifest/result/words, SRT, chapters.txt, plan.resolved,
  метаданные, простые варианты обложки 16:9 и ПАКЕТ.txt. Обложки отличаются размещением
  текста, не выдавай их за три полноценных творческих концепции.

## Полный рабочий путь [Г]

1. Прочитай prefs brand.niche / niche_profile и заметки. Запиши аудиторию, задачу,
   язык, выбранный жанр и ограничения в brief.md. Ниша не выводится из чужого CTR.
2. Упаковка из четырёх элементов: название, обложка, хук, вступление. В packaging.md
   укажи одно честное обещание и где именно оно выполнено.
3. Сценарий + раскадровка + таблица блоков: время, задача зрителя, кадр, речь,
   локальные источники, результат блока, переход. Длительность блоков по задаче;
   3-7 минут [Г] - вариант для эссе, не канон интервью/урока/музыкального видео.
4. Карточки каждого тейка (plan-format.md), сравнение дублей, итоговая шкала и стыки.
   Объяснение может дать ответ сразу, затем доказывать, показывать исключения.
5. План schema 1.4 -> validate -> render -> qa. Для полного автоматического пути all.
   QA длинного декодирует весь файл и звук, проверяет размер, длительность, громкость,
   сообщает кандидаты чёрных/тихих мест; выборка кадров ограничена памятью.
   Он не оценивает драматургию, смысл, фонетические обрезания или качество дубля.
6. meta: напиши metadata.draft.json вручную по нише, включи реальные главы;
   автозаготовка не считается хорошей упаковкой. cover: отдельная проверка 150 px.
7. Финальный qa --strict, кадры и review; затем обязательный просмотр движения
   и звука ВСЕГО файла. motion_audio остаётся manual, пока такой просмотр не сделан.
   review по кадрам этот пункт не закрывает. Если проигрывания/прослушивания нет,
   итог: технический экспорт выполнен, ручная приёмка частичная. package это сохраняет.
8. package: ПАКЕТ.txt. Не называй учебный технический файл готовым коммерческим роликом.
   Вау-тест [Г] вспомогательный, публикация и результаты отдельно.

## Длинное -> короткое

clips создаёт JSON-планы кандидатов по доступным сигналам (громкость, склейки,
слова, heatmap URL при наличии). Локальный файл heatmap не имеет. Без Whisper или
transcript смысл речи и субтитры не гарантируются. Автоматические три сцены не
равны редакторским тейкам. Проверь каждый кандидат, контекст, границы и author_layer,
затем render / qa. Не обещай автоматически лучшие фрагменты или готовые шортсы.

## Не проверенное универсально

Учебная приёмка не подтверждает качество любого жанра и любого длительного исходника.
Нагрузка, 1920x1080/60 fps и внешние TTS требуют отдельного прогона на целевой машине.
Ограничения и результаты конкретного запуска: acceptance/REPORT.md.
