## 1. Режим задачи и приоритеты

Сначала различить:
- **Разработка скилла**: пользователь просит встроить знания, доделать инструменты или научить
  следующего агента. Изучить код, изменить маршруты/шаблоны/проверки, тестировать, вернуть архив.
  НЕ требовать реальный продукт, канал, рекламный бюджет и оффер. Для тестов использовать
  явно синтетические данные. Не создавать рекламную кампанию от лица пользователя.
- **Производство рекламы**: конкретный продукт/канал/креатив. Пройти этот маршрут.
- **Выбор монетизации**: продукта нет, но известна аудитория. Предложить 2-3 направления [Г]
  и критерии допуска из `reference/ad-offers-traffic.md`; не выдумывать действующую партнёрку.
- **Обучающий макет**: использовать вымышленный продукт с видимой надписью «Учебный макет»;
  реальные цены, скидки, промокоды, выплаты и ссылку не подставлять.

Применять v3.4 к рекламе ПЕРЕД старыми материалами research. При конфликте: применимые
официальные ограничения и честность > релевантные измерения > практические советы > гипотезы.
Старые отступы safe-зон, число роликов, 4-5 дней и доли бюджета не являются нормами площадок.
Скилл не гарантирует конверсий, дохода или качества без реального финального просмотра.

## 2. Входы и выбор формата

Извлечь из задания, памяти и файлов: цель/событие; продукт/продавец/ссылка; оффер/модель оплаты;
аудитория/страна/язык/возраст; размещение/аккаунт; видео/фото/логотип/права;
бюджет/допустимый убыток/срок/брендбук; доступная аналитика/SubID/расходы.
Не спрашивать известное повторно. Собрать только критические пробелы одним коротким сообщением.
Не переносить VioraStudio, VPN, Telegram и чужие реферальные ссылки из примеров в новый проект.

Различить четыре формата по задаче, а не по слову «баннер»:
| Формат | Задача | Выход |
|---|---|---|
| Рекламный оверлей | Предложение внутри другого видео | Плашка/стикер/анимация + интервалы |
| Статичное объявление | Переход из размещения | PNG/SVG + точный текст/CTA/дисклеймер |
| Рекламный шортс | Самостоятельная полезная демонстрация | Сценарий, MP4, субтитры, CTA |
| Фоновая полоса / сплит | Компоновка, иногда геймплей | Видео-композиция; не оффер и не доход |

При неоднозначном «баннер сверху» спросить, реклама это или оформление. Не добавлять
геймплей к интерфейсному уроку автоматически. Выбирать одну основную воронку.

## 3. Производственный конвейер

1. Записать связку: аудитория -> полезный контент -> предложение -> переход -> целевое действие.
   Назвать событие точно: просмотр, клик, подписка, подтверждённый лид, продажа или оплаченный охват.
2. Проверить допуск по `reference/ad-offers-traffic.md`. Неизвестное блокирует запуск,
   но не честный черновик. Заполнить `campaign.json`, не смешивать его с `plan.json`.
3. Разработать 2-3 РАЗНЫЕ концепции: проблема/решение, демонстрация, сравнение процессов.
   Для каждой: инсайт аудитории, одно сообщение, доказательство на экране, хук, payoff,
   один CTA, гипотеза и риск. Выбрать по ясности и наличию доказательства, не по громкости.
4. Прочитать `reference/ad-creative.md`. Записать дословный текст и раскадровку:
   время | исходник/действие | текст/голос | доказательство | звук | CTA/оверлей.
   Сначала монохромная иерархия, затем цвет. Сперва дать пользу и результат, затем переход.
5. Собрать по существующему `schema/plan.schema.json`, запустить validate/render для видео.
   Анимированная нижняя плашка: `reference/live-banner.md`. Произвольные размеры/интервалы
   НЕ появляются от записи в campaign.json: применить монтажный инструмент и проверить файл.
   Статичное объявление собирать отдельным локальным SVG/PNG/редактором; не выдавать MP4 за PNG.
6. Проверить `reference/ad-qa.md`: смысл/факты/права, полный финальный MP4 в движении и со звуком,
   телефонный размер, UI площадки, субтитры, точную ссылку и QR в закодированном видео.
   Исправить, пересобрать, повторить QA. Не ставить passed по одному успешному рендеру.
7. Описать эксперимент по `reference/ad-analytics.md`: метрика, источники событий, атрибуция,
   окно наблюдения, полные затраты, предел убытка и остановка. Не оплачивать ничего молча.
8. Записать доказательства и SHA-256 финального файла; запустить ad-check --stage launch.
   Для видео также qa и release-check. Только после согласования конкретного запуска
   переходить к внешним действиям. Код не публикует и не тратит деньги.

## 4. Файлы и команды

Шаблоны: `templates/advertising/brief.md`, `concepts.md`, `storyboard.md`, `qa.md`,
`experiment.md`; машинная карточка: `schema/campaign.example.json`, контракт:
`schema/campaign.schema.json`. Учебный пример: `examples/advertising/captions-training.md`.

Команды из корня скилла:
```bash
python tools/shorts.py ad-init out/my-ad
python tools/shorts.py ad-render out/my-ad --ratios 9x16 1x1 4x5 16x9 --platforms youtube_shorts tiktok reels
python tools/shorts.py ad-seal out/my-ad --artifact banners/banner-9x16.png
python tools/shorts.py ad-links out/my-ad --ids a-problem,b-demo,c-compare --subid-param subid
python tools/shorts.py ad-check out/my-ad --stage draft
python tools/shorts.py ad-check out/my-ad --stage launch [--today YYYY-MM-DD]
python tools/shorts.py ad-metrics out/my-ad/metrics.json --log out/my-ad
python tools/shorts.py paid status|reset
python tools/shorts.py release-check out/my-ad
```

Что делает каждая команда (и чего НЕ делает):
- `ad-render`: рисует статичные баннеры из campaign.json (поле `creative`), по каждому формату цветной и
  монохромный файл, превью 360 px и `banner-report.json` (контраст, переполнение, телефонный минимум, safe-зоны
  из schema/safe_zones.json, дисклеймер). Не оценивает смысл, права и реальный интерфейс площадки.
- `ad-seal`: записывает путь и SHA-256 готового файла в final_artifact. Ничего не одобряет.
- `ad-links`: по одной метке-ссылке на креатив (UTM/SubID), links.csv и links.md. Подписанные партнёрские
  ссылки не меняет. Уровень атрибуции только предлагает: подтверждает его реальный клик и отчёт сети.
- `ad-metrics`: арифметика денег и воронки по числам пользователя; статус preliminary/final, решение
  STOP/INSUFFICIENT_DATA/HOLD/REPEAT/REVISE_OR_STOP по заранее заданным лимитам; журнал experiments.jsonl.
- `paid`: реестр оценок платных API (см. «Согласование платных API»).

ad-init не перезаписывает существующие файлы, создаёт документы с пустыми входами.
ad-check сохраняет ad-qa-draft.json и ad-qa-launch.json раздельно; ad-qa.json - последний результат.
Повтор той же стадии заменяет её снимок; для истории копировать отчёты в версионный каталог.
ad-check draft проверяет структуру; успешный draft НЕ даёт ready_for_launch.
launch требует заполненных доказательств, согласования и совпадения хэша финального файла.
Проверка не открывает ссылки, не подтверждает истинность самоотчёта и не оценивает красоту.
Повторять после любой смены продукта, файла, CTA, ГЕО, площадки или условий.
Если есть campaign.json или release.json содержит advertising=true, release-check вызывает
ad-check launch. Отсутствие карточки в обозначенной рекламе блокирует готовность.
Старый нерекламный путь сохраняется. release-check теперь ищет слова-маркеры рекламы (промокод, партнёрская ссылка,
utm_, ref=, скидка, #ad, реклама, спонсор и др.) без campaign.json и блокирует выдачу, пока человек не создаст карточку
или не запишет `advertising=false` и `advertising_reason` (10+ символов). Это эвристика: отсутствие срабатывания
не доказывает, что ролик не реклама.

## 5. Достоверность и полномочия

Внутренние метки: [П] официальное правило + URL/дата/область; [О] совет практика;
[Г] гипотеза/макетный ориентир; [М] измерение + период/выборка/условия; [НП] не проверено.
Для рекламного обещания использовать подтверждённые применимые факты, а не [О]/[Г]/[НП].
Не заявлять «бесплатно», «лучший», «скидка», «без комиссии», скорость или заработок без условий.
Не выдумывать опыт пользователя, отзывы, экспертов/врачей/звёзд, доходные скриншоты и дефицит.
Не представлять азартные игры способом заработка; не адресовать возрастные офферы детям.
Не строить работу на клоакинге, покупке аккаунтов и обходе блокировок.
UGC = естественная подача реальной демонстрации, не право аватара выдумать личный опыт.
Авторский слой/указание автора не заменяет коммерческую лицензию. Поиск/spy не дают прав.
Не публиковать, не писать рекламодателям, не оформлять платные услуги и не тратить средства
по одному разрешению создать черновик. Согласовать объём, канал, срок и бюджет отдельно.

## 6. Выдача и обучение скилла

Выдать только нужный объём: файлы макета/видео при доступном рендере; иначе производственное
ТЗ с честной пометкой, что это не файл изображения. Отделить зрительское описание от отчёта.
Отчёт: цель/связка; подтверждено/неизвестно; точный креатив; таймлайн/звук;
разные концепции/гипотезы; эксперимент; QA/блокеры. Превью не называть готовым к публикации.
Для обновления скилла показать изменённые компоненты и фактически выполненные тесты,
сохранить старые инструменты и память, приложить переносимый архив. Тесты кода не равны
проверке поведения другого ИИ: отдельный агентский прогон только с согласия пользователя.

Первоисточник и карта покрытия: `docs/advertising-source-map.md`.

## Согласование платных API (v3.5: бюджет и реестр)
Потенциально платные HTTP-запросы TTS OpenAI/ElevenLabs и генерации обложек OpenAI/Gemini заблокированы.
Для запроса нужны оба условия: `SHORTS_ALLOW_PAID=1` и `SHORTS_PAID_BUDGET=<USD>` больше нуля.
Каждый запрос записывается в `paid-ledger.json` (путь: SHORTS_PAID_LEDGER или SHORTS_MEMORY) с оценкой
(TTS 0.30 USD за 1000 символов, картинка 0.25 USD): превышение остатка блокирует запрос до отправки,
битый реестр блокирует всё (fail closed). `paid status` показывает остаток, `paid reset` обнуляет реестр.
Оценки не биллинг провайдера; реальный счёт сверять в кабинете. Бюджет согласовать с пользователем
на конкретный объём, после задания снять флаги. Флаги не разрешают публикацию и закупку трафика.
Кэш озвучки и локальная сборка обложек из кадров не требуют платного запроса.
Если API заблокирован, не объявлять генерацию успешной: использовать fallback или назвать блокер.

## Учебный статичный маршрут

Для задания «ничего не продвигаем, покажи учебный макет»:
1. Использовать известную аудиторию; если её нет, выбрать и явно назвать учебное допущение.
   Не запрашивать настоящий оффер, аккаунт и бюджет. Не исследовать десятки каналов:
   это исключение из общего niche-entry для небольшого внутреннего учебного задания.
2. Прочитать ad-creative.md и ad-qa.md; остальные рекламные справки - по нужному разделу.
   ad-init создаёт пустой sidecar; задать goal=training_comprehension,
   training_product=true, monetization=training, creative_type=static_ad.
   Оффер/ссылка остаются null, spend_limit=0, publication_approved=false.
3. Записать три смысловых концепции и выбрать одну по доступности честного доказательства.
   Вымышленный UI пометить «Учебный макет. Не запись продукта». Не подставлять чужой бренд.
4. Собрать монохромный, затем цветной SVG/PNG доступным локальным инструментом.
   Проверить реально установленный шрифт: имя font-family не доказывает отсутствие fallback.
5. Открыть файл и телефонное уменьшение; измерить размеры, сохранить исходник и SHA-256.
   Уменьшение на экране не называть проверкой физического телефона или UI площадки.
6. У motion_audio/subtitles указать applicability=not_applicable, passed=false и конкретное
   evidence (нет временной шкалы/аудио/субтитров). Другие проверки так исключать нельзя.
7. Выполнить ad-check --stage draft. При отрицательном контрольном запуске --stage launch
   ожидать отказ именно из-за учебного продукта; отдельные отчёты сохраняются автоматически.
   Не создавать фиктивный MP4/release.json. Не заявлять эффективность и допуск к публикации.
8. Передать PNG, редактируемый исходник, концепции, QA и ограничения. Внутренний CTA может
   быть действием читателя («Сверь с оригиналом»), без выдуманной кликабельной ссылки.

## Учебный видео-маршрут
Пример: `examples/advertising/video-training/` (plan.json, diff-demo.html, campaign.json, ad-video-training.mp4).
1. Продукт вымышленный: записи экрана, оффера и ссылки нет. Анимацию рисует HTML, подпись «Учебный макет»
   видна в панели. Это демонстрация конвейера, не рекламная кампания.
2. Поля панели (name, message, action, qr_url, handle) лежат в `layout.bottom`, НЕ внутри `animation`:
   validate теперь отказывает, иначе панель молча показывает запасной текст «VPN в Telegram».
3. `validate` -> `render` -> `qa` -> открыть contact-1.png и qa-frames, описать увиденное, затем
   `ad-init`/campaign.json (creative_type=advertising_short, overlay.start/end и rectangle панели),
   `ad-seal` для MP4, `ad-check draft`; launch для учебного продукта должен отказать.
4. Подпись/слова на экране не должны перекрывать друг друга: заголовок рисовать внутри HTML-сцены,
   субтитры оставлять нижней трети центра.

## Боевой запуск: чек-лист 1.7.0
Скилл не знает реального оффера и не публикует. Перед настоящим запуском человек обязан:
1. Заполнить карточку оффера из письменных условий сети и приложить доказательства (не старше `evidence_max_age_days`,
   по умолчанию 30 дней).
2. Назначить проверяющего-человека (`reviewer`), отличного от `author`; он подтверждает QA, права и утверждения.
3. Заполнить `disclosure` для affiliate/fixed_placement и включить метку платформы
   (YouTube: платная реклама в Studio; TikTok: переключатель раскрытия; Instagram: paid partnership).
4. Иметь минимум 2 варианта с разными концепциями и гипотезами; атрибуцию по креативам заявлять только при реальном SubID/уникальной ссылке.
5. Проверить, что ссылка кликабельна там, где её дают: URL в описании и комментариях YouTube Shorts некликабельны
   (YouTube Help, проверено 2026-10-20), кликабельны ссылки профиля канала, brand deal и Posts.
6. Просмотреть финальный файл на телефоне с интерфейсом площадки; заполнить qa доказательствами.
7. Согласовать бюджет, срок, площадку и публикацию отдельно; `ad-check launch` + `release-check` без блокеров.
8. После публикации вести `ad-metrics` и решать по лимитам; не масштабировать preliminary-данные.
