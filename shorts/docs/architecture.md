# Архитектура SHORTS 1.0

Короткий план, который агент показывает пользователю перед стартом (раздел 5.2 промпта).

## Поток
```
prefs/intake -> plan.json (модель пишет смысл) -> validate (схема + правила)
  -> render: TTS (слова+тайминги) -> длины сцен -> адаптеры (клипы центра) -> субтитры ASS
             -> графика бренда (метки, CTA, QR, низ) -> звук (голос, музыка с ducking, SFX, loudnorm)
             -> покадровая сборка numpy -> ffmpeg (libx264 + libass) -> manifest.json
  -> qa (15 пунктов + 20 чек-лист, по пикселям) -> meta (подписи) -> cover -> выдача + напоминание
```
`manifest.json` записывает, что и где нарисовано (коробки, время, цвета). QA сверяет его с кадрами готового ролика.

## Ключевые решения
- **Сборка кадров в Python, а не HTML-композиция.** Нужен полный контроль над тем, что где нарисовано (для QA)
  и без Node-рантайма. HyperFrames/Remotion взяты как источник правил, не как зависимость.
- **Захват сайтов: CDP screencast** вместо `record_video` Playwright: чёткие кадры в размер панели с метками времени,
  что позволяет ретайм (скорость) и зум камеры на клик без потери синхронности.
- **HTML: виртуальное время.** Работает с любой страницей, повторяемо; страницы с `__seek` получают точное время.
- **TTS: edge-tts по умолчанию** (бесплатно, есть границы слов на русском и английском), с повторами и цепочкой
  запасных. Тайминги без границ слов помечаются как оценка и QA пишет, что синхронность не измерена.
- **Субтитры через libass** с позициями из движка: QA знает коробку каждой порции и проверяет её пикселями.
- **Моменты для эдитов:** heatmap YouTube как главный сигнал (реальное поведение), плюс громкость и склейки
  через ffmpeg (без тяжёлых зависимостей), плюс речь, если есть транскрипт.
- **Всё, что считается, считает код** (safe-зоны, контраст, длина, громкость, QR); вкус (хук, слова, выбор кадров) у модели.
