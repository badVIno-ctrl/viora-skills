## (а) Интервью / стендап → вертикальные Shorts с нарезкой лучшего
---------------------------------------------------------------------

### А1. Длительность и структура
- Клип 12–35 с, история с подводкой до ~45 с, если развязка стоит того. Сильнейшая реплика — в первые 1–2 с, говорящий уже в процессе фразы; длинные вопросы/предыстория/«ну вот» вырезать. Конец: на последнем слове, жёсткий склейкой, без аутро. [S] https://clippingculture.com/blog/podcast-clipping-workflow
- Первый кадр = хук (результат/удивление/вопрос), первая реплика его продолжает; «бит» (смена кадра/зум/текст/SFX/смена темы) каждые 2–3 с; паузы >1 с вырезать. [S] https://prepublish.ai/guides/youtube-shorts-retention
- Концовка-петля: без «пока-пока»; последняя фраза должна стыковаться с первой (проверка: прочитать последнюю+первую подряд). [S] тот же prepublish.
- Аудит 1670 клипов: hook с оценкой A у 15% клипов; по типу момента A-хук получали: смешное 50%, сильное мнение 39.5%, конфликт 21.6%, «раскрытие» 10.9%. Длительность хук не предсказывает (медиана 46 с). Слабые открытия: мягкий переход, открытый вопрос, местоимение без контекста. [S] https://nysos.io/en/statistiques-clipping (оценки их движка, не просмотры)
- Стендап: 20–60 с, от сетапа до смеха; оставить звук зала, закончить «через один такт» после панчлайна, сетап резать жёстко, не брать шутки с колбэками; подпись панчлайна — на долю секунды ПОСЛЕ сетапа, не раньше. [S] https://optimaclip.com/blog/repurpose-stand-up-comedy-sets-into-clips
- Тайминг пауз: между фразами оставлять 0.2–0.3 с; ускорение речи 5–10% допустимо [S] clippingculture; для соло-говорящей головы резать тишину >0.5–0.7 с, для объяснялок >0.3–0.5 с [S] https://monty.fast/blog/how-to-edit-talking-head-videos/
- Для подборки шуток (стандап/видео RTifScOdX-U) [Я]: 4–6 шуток по 8–20 с, каждая = сетап (≤5 с после жёсткой нарезки) + панчлайн + 0.5–1 с реакции; общий хронометраж 45–75 с; без тайтла «шутка №N» дольше 0.6 с; жёсткая склейка по звуку смеха.

### А2. Как выбирают «самое сочное»
- Что оценивают OpusClip/Vizard (5 сигналов): всплески громкости (смех, повышенный голос), плотность «хук-слов» (biggest/secret/truth/never/mistake), законченность мысли, структура хука (вопрос / спорное утверждение / «я» история), длинный монолог одного говорящего лучше перебивок. [S] https://kompozy.io/ai-podcasting/clip-detection-podcasts
- OpusClip virality: 0–99 из подоценок Hook / Flow / Value / Trend. [S] https://help.opus.pro/docs/article/virality-score ; сводка https://github.com/osbytes/reelsaw/blob/main/docs/RESEARCH.md
- Чего они пропускают (поэтому нужен ручной/LLM-проход): инсайдерский контекст, медленный payoff, отрицание/разворот, цифры сказанные без эмфазы, ожидаемые раскрытия. [S] kompozy (выше)
- Правила человека-редактора: смотреть транскрипт, а не только громкость («громкость/смех/крик ненадёжны»); начать с первого предложения, которое работает без контекста; кончать, когда мысль замкнута («если у незнакомца ощущение недосказанности — взять следующее предложение»); 3–6 кандидатов на 10 мин разговора; отбраковать: смех без сетапа, реакцию без контекста, кроссток, незакрытый список, опору на график. [S] https://clipflap.com/blog/how-to-find-the-best-moments-in-a-podcast
- Рубрика для LLM-скоринга: hook, flow, value, standalone; признаки: плотность смеха, пики темпа/энергии речи, вопрос/хук в первые 3 с, доля кадров с лицом; смех через 2–3 с после реплики = маркер payoff; сегменты по темам с ~20% перекрытием, 3 прогона → медиана, отсечка max(25, median − 1·MAD). [S] https://github.com/osbytes/reelsaw/blob/main/docs/RESEARCH.md
- Цифры/суммы («$100 000») — это ровно тот сигнал, который сами модели пропускают (kompozy) → добавить регэксп на числа/валюту как ручной бонус [Я].
- Для слабой модели [Я]: не просить «найди лучшее», а давать чек-лист 0/1 по 6 пунктам (хук ≤2 с без контекста; есть число/конфликт/смех; мысль закрыта; 15–45 с; не зависит от «как я говорил»; нет кросстока) и сортировать по сумме.

### А3. Вертикальный кроп: почему «полоса 16:9 по центру» — плохо
- 16:9 в кадре 1080×1920 = полоса 1080×608 = 31.6% высоты (≈68% — бары/пустота, ~1300 px нужно чем-то залить). Лицо — крошечное; видео выглядит «плавающей полосой», не нативно. [S] https://videotoolery.com/blog/landscape-video-to-vertical-reel , https://clippingnet.com/horizontal-to-vertical-video/
- Это и есть «полу-шортс-полу-лонгформ» из скриншота пользователя (баннер сверху, полоса 16:9 в центре с размытыми краями, реклама снизу) [Я].
- Альтернативы (4 способа): трекинг-кроп 9:16 на весь экран (оставляет 31.6% ширины 16:9); 4:5 (45%); stacked-split (2 области, полная ширина источника); fit+blur (оставлять только для широких/групповых/экранных записей). По контенту: один говорящий → трекинг-кроп; двое/геймплей/слайды → стек; экран/спорт/текст по краям → fit. [S] clippingnet (выше)
- Центр-кроп без трекинга — худший вариант: режет говорящих на краях; для двоих — стек лиц сверху/снизу; лица держать в верхней половине, середину оставить под субтитры. [S] https://www.conbersa.ai/learn/podcast-clip-vertical-video-format , clippingculture
- Кроп менять на склейках или при смене говорящего, не по таймеру; глаза — в верхней трети. [S] clippingnet
- Резкость: кроп 9:16 из 1080p даёт всего 608 px по ширине (мягко); из 4K = 1215×2160 (чётко). [S] clippingnet. Исходники пользователя 1280×720 [ffprobe] → для 1080×1920 нужен апскейл ×2.67 (1920/720) [Я]; для панели 1080×960 из 720p — ×1.33 (мягко, но терпимо).
- (!) Арифметика CapCut-туториала [Я]: 16:9 «Fit» в 9:16 имеет высоту 608 px, чтобы залить 1920 px, нужно 316%, а не 240%. Значит «240» в туториале относится к другому базовому масштабу/исходнику. Не переносить число 240 буквально; в коде считать scale = 1920/высота_исходника_в_px.

### А4. Split-экран и «сколько места панелям»
- Две панели 9:16 → каждая 1080×960 (50/50); одинаковая ширина кропа у обоих, чтобы лица были одного размера; лица должны быть разнесены > 1/6 ширины исходника, иначе один общий кроп; максимум увеличения 2.6×; субтитры у шва (≈44% высоты снизу), а не внизу — там перекроют нижнего. Сплит использовать для реплик/реакций/спора; длинный ответ/монолог → один кроп. [S] https://klyply.com/split-screen-podcast-clips/ ; Skapo: https://skapo.io/resources/podcast-split-screen-shorts-layouts
- Схема «основное сверху + удерживающий луп снизу» (Subway Surfers и т.п.): две примерно квадратные панели, нижняя — спокойный луп, не должна конкурировать сюжетом с основной; нужна лишь чтобы кадр не был статичным. [S] https://crayo.ai/glossary/split-screen-video , https://korpi.ai/best-ai/split-screen
- Точных % для трёх панелей в источниках нет. Мой расчёт под «сверху машинка / центр интервью / снизу реклама» [Я]: верх 1080×384 (20%) — чистый луп без текста (верхние 230 px всё равно закрывает UI Shorts); центр 1080×1056 (55%, y 384–1440): кроп 9:8 из 1080p = 1215×1080 без апскейла, ≥55% высоты вместо 31.6%; низ 1080×480 (25%) — реклама, но CTA/лого размещать в y≈1250–1570 (нижние 346 px занимает UI). Чем больше панель с контентом, тем меньше «полу-лонгформа»; сверхмалая панель рекламы ≤ 20–25%.
- Safe-зоны 1080×1920, YouTube Shorts: сверху 230 px (12%), снизу 346 px (18%), справа 86 px (8%); TikTok: 192/384/108; Reels: 154/480/130. [S] https://edicionvideopro.com/en/editing-techniques/916-aspect-ratio-guide-vertical-video-for-tiktok-reels/ ; близкие цифры https://www.conbersa.ai/learn/podcast-clip-vertical-video-format

### А5. Как автоматизируют (что повторять)
- OpusClip: активный говорящий по голосу+движению, плавно подводит рамку; лучше всего при одном явном спикере; ручной «Tracker» по клику на объект; про авто-сплит при двух спикерах в доке не сказано. [S] https://help.opus.pro/docs/article/subject-tracking
- AutoFlip (Google): (1) детект шотов по гистограмме цвета с буфером всего шота; (2) лица/объекты (MediaPipe TFLite, веса по классам); (3) политика камеры на шот: stationary / panning (константная скорость) / tracking; (4) боксы дрожат → подгонка гладкой полиномиальной траектории (евклидова норма); (5) если не влезает — паддинг однотонным цветом или размытым кадром. [S] https://research.google/blog/autoflip-an-open-source-framework-for-intelligent-video-reframing/
- Klap Reframe 2: разделяет webcam/экран, следует за лицом или saliency-точкой; авто-сплит для подкаста. Vizard: идентификация спикеров + авто-раскладки для нескольких. [S] reelsaw RESEARCH.md; https://vizard.ai/blog/vizards-speaker-identification-just-got-smarter
- Active speaker detection (губы+аудио): Light-ASD 94.1 mAP, ~1.0M параметров, достаточно ~5 fps на трек; дешёвая замена — диаризация, привязанная к трекам лиц, + гистерезис/минимальная длина шота против «дёрганых» переключений. [S] reelsaw RESEARCH.md → https://github.com/Junhua-Liao/Light-ASD
- Submagic: авто-субтитры, эмодзи, подсветка ключевых слов, анимации, b-roll. [S] https://www.submagic.co/features/auto-video-editor

### А6. Субтитры
- 2–4 слова за раз; строка из 3 слов ≈ половина ширины кадра (~540 px); белый + чёрная обводка; вычитывать авто-субтитры. [S] clippingculture
- Не больше 2 строк, 16–20 символов/строка, 3–5 слов/чанк, минимум 0.7 с на чанк, ≤17 симв/с; положение ≈60–70% высоты; «караоке»-подсветку А/Б-тестировать, не считать заведомо лучше. [S] reelsaw RESEARCH.md
- Блок: верх 35–45% высоты (672–864 px), низ 60–70% (1152–1344 px), ширина 80–90% (864–972 px). [S] conbersa. В сплите — у шва (Klyply).

### А7. Зумы / punch-in / частота смен
- Punch-in ≤110–120%, чередовать норм/крупно; смена картинки раз в ~4 с. [S] monty.fast (выше)
- Другое мнение: 10–20% крупнее; <10% не видно, >30% «прыжок»+мыло на 1080p; держать ≥3–4 с; раз в 8–12 с (2–3 на 30-секундный клип); снап (1 кадр) для комедии, медленный дрейф ~0.5 с для интервью; ставить на смысл (payoff-реплика, смена эмоции), не по таймеру и не на паузах/паразитах. [S] https://autoclip.dev/blog/how-to-use-punch-in-zoom-effect ; «10–25%» https://www.usevyra.com/prompts/talking-head-punch-ins
- Согласование [Я]: «событие» (любое: зум, смена кропа, текст-акцент, b-roll, SFX) каждые 3–4 с; именно punch-in — не чаще раза в 8–12 с и не дольше удержания 3 с.
- Музыка под голосом: ≥20 дБ ниже речи [S] monty; 20–25 дБ [S] https://www.revid.ai/blog/shorts-video-edit ; мастер ≈ −14 LUFS, true-peak запас ≥1 dB [S] monty / ffmpeg-micro (ссылка в блоке В).

## (б) Эдит из фильма под бит
---------------------------------------------------------------------

### Б1. Что общего в двух туториалах (прочитаны целиком кусками) и в других источниках
Туториал 1 (tjmbz1k9wsU, CapCut, «Быстрее пули» + «Кот в сапогах»), 7 этапов: референс (новичкам — повторять готовый эдит) → исходники в 4K (плохой кусок вступления апскейлили нейросетью) → нарезка лучших кадров → синхронизация с битом (слушать трек, класть кадры на удары; во втором эдите — маркеры) → переходы/эффекты/анимации (маска-«чёрные полосы», широкоугольный, edge glow) → оверлеи (видео на чёрном, режим «Экран») → цветокор (яркость/контраст/резкость/чёткость, частицы, лёгкая виньетка, мигание ключами под музыку). Вступление «текст за персонажем» (дубль, маска, текст между слоями, составной клип под эффект, глаза — отдельная копия с маской и насыщенностью). Саунд-дизайн — последним: удары, взмахи, вжухи на переходах. Важно: фильмы 24 fps, при замедлении даже на 25% рвётся → «плавное слоу-мо» = «оптический поток».
Туториал 2 (wwMeX-qDfoA, CapCut, «Волк с Уолл-стрит»): материалы → черновая нарезка (>10 клипов «эпичных» кадров: герой уверенно идёт, жестикулирует, ярко эмоционирует, в центре внимания) → вступление-диалог (в примере ~9 с, 4 реплики: «сколько зарабатываешь?» — «70 000 за месяц» — «хорош заливать» — «я серьёзно»; «диалог должен цеплять и не быть затянутым, иначе пролистают») → найти у трека «хук» (переход куплет→припев/яркий момент), обрезать музыку перед ним и поставить на конец диалога, музыку растянуть назад, чтобы звучала и в начале → громкость: музыка −10 дБ, голос +15 дБ (до красной зоны) → маркеры [M] на удары бочки → 9:16, масштаб ≈240 (с оговоркой из А3), лицо по центру, копирование свойств Ctrl+Shift+V → кривая скорости: ~10× → ~0.5× → снова ускорение, оптический поток, копировать кривую на клипы → Sharpen Edges (дубль), Chromatic Aberration → русские авто-субтитры (вычитать), анимации Grow на входе / Blur на выходе → лёгкий шейк (Sway), edge glow ≈20, фильтр «Pine» 100%, чёрный шум с инвертированной круглой маской (не на лицах) → SFX: звук денег на «money»-реплике, riser перед хуком.

Общее у обоих и у других источников:
1. Сначала референс и лучшие исходники (4K/макс. качество).
2. Сильный эмоциональный «вход» (диалог/интро) → музыка стартует на пике («хук») после реплики.
3. Монтаж ведёт музыка: маркеры на кик/снейр, смена кадра на маркер.
4. Скорость — кривыми (быстро → замедление на ключевом моменте → снова быстро), с оптическим потоком для 24 fps.
5. Эффекты умеренно (резкость, хроматика, шейк, глоу, виньетка), оверлеи режимом Screen.
6. Саунд-дизайн в самом конце: riser → hit на дроп, whoosh на склейки.
7. Цветокор и текстуры (зерно/частицы) финишно.

Дополнительные источники:
- Beat-sync, CapCut: 1 бит = 1 клип (бёрст 4–8 бит), 2 бита = «энергично, но читаемо» (8 клипов на 16 бит после дропа), 4 бита = медленные удержания; даунбит (бит 1) — смена сцены, слабые доли (2,4) — мелкие смены; маркировать ≥16 битов; авто-биты чистить вручную; переходы — на границах фраз (каждые 8/16 бит); моушен-акценты — только на сильных ударах; подгонка скорости ±5–10%. [S] https://cursa.app/en/page/beat-based-editing-in-capcut-syncing-cuts-transitions-and-motion-to-music
- Структура бит-синк эдита: 15–30 клипов, 10–30 с; 0–1 с первый склейка на первый бит; 1–15 с резка на каждый бит, чередовать типы планов; 15–18 с пауза/слоумо перед дропом; дроп: резка на половину бита (≈0.21–0.25 с при 120–140 BPM [Я]), зумы и вспышки; белая вспышка на первом бите дропа; на самых громких ударах — быстрый зум вместо склейки; финал: последний удар → жёсткий чёрный; допуск кадр-в-кадр («2 кадра мимо видно»). [S] https://www.usevyra.com/formats/beat-synced-edit
- Монтаж-ритм: планы ~0.6–1.0 с на транзиентах кика/снейра (пример: резка каждые 0.8 с), реveal ровно в кадр дропа, перед дропом riser, импакт-стингер в кадр дропа, flash 0.9→0 за 0.25 с, whoosh на раскрытии. [S] https://github.com/iart-ai/ad-video-skills/blob/main/skills/launch-video/references/launch-structure.md
- Спидрамп: 100% → 20% → 100%, замедление привязать к точному кадру удара/взгляда; не злоупотреблять; чистый рапид — только с 96–120+ fps, при 24 fps артефакты неизбежны. [S] https://www.screenweaver.ai/ru/film-techniques/time-motion/speed-ramp ; «Velocity» = плавный разгон, резкие пики, возврат к норме [S, сниппет поиска] https://capcut-russia.ru/howto-speed-velocity/
- Для плавных эдитов рекомендуют 60 fps (120/240 для слоу-мо), экспорт 1080p+; битрейт «от 20 Мбит/с» — заявление блога, для Shorts избыточно (см. В). [S] https://whitetools.app/blog/kak-sdelat-edit-v-capcut

### Б2. Рецепт для генератора [Я, собран из выше]
Тайминг (25–30 fps вывод):
- 0.0–2.5/5.0 с: реплика героя (2–5 с хотя бы одна законченная «мыслью» строка; туториал-2 использует ~9 с — верхний предел). Музыка под голосом −10 дБ (абсолютное, CapCut), голос +15 дБ (или правило 20–25 дБ относительно); на последнем слове реплики — riser 1–2 с.
- Дроп: склейка + белая вспышка 0.25 с (0.9→0) + hit-SFX + chromatic-aberration/шейк 4–6 кадров.
- 2.5–~20 с после дропа: BPM 120–140 → бит 0.43–0.5 с. Первые 8 битов: 1 план/бит (0.43–0.5 с); дальше смешивать 1 и 2 бита (0.5–1.0 с); 1 «удержание» 1–1.5 с (слоумо 0.5×) на лучшем кадре; финал последний удар + чёрный.
- Всего 15–30 клипов, 15–30 с.
- На каждом клипе лицо по центру; план «эпичный»: герой в центре, действие/эмоция.
- Спидрамп-кривая на склейках: вход ~10× (первые 3–4 кадра) → 0.5× на ударе → к 1.0×; включать оптический поток (в ffmpeg: minterpolate mi_mode=mci, mc_mode=aobmc, me_mode=bidir, vsbmc=1; scd=fdiff; без оптического потока слоумо 24 fps рвётся; ghosting на сложных сценах возможен).
- Субтитры: поверх реплики, 2–4 слова, вход Grow, выход Blur; под дропом — без субтитров или 1 ключевое слово.
- Цвет: контраст+, резкость+, виньетка, зерно/частицы; без перегруза.

## (в) Причины «лагов» в готовых шортсах и профессиональные меры
---------------------------------------------------------------------

### В1. Что видно на файлах пользователя [ffprobe]
- SHORTS-PREVIEWS: все 4 ролика 1080×1920, h264, **25 fps**, битрейт видео 1.31–3.03 Мбит/с (interview 1.76, usovich 1.31, brat 3.03, slovo 2.73). У YouTube рекомендация для 1080p: 8 Мбит/с (30 fps) — то есть 2.6–6× ниже.
- Исходники /tmp/w/src: брат/интервью/шутки/словопацан — 1280×720, 25 fps (AV1 webm); верхний баннер «машинка» (top.mkv) — 1280×576, **60 fps**.
- 60 → 25 fps = делитель 2.4 (неравномерный: чередуются шаги 2 и 3 кадра: 2,3,2,2,3) → рывки на едущей машинке [Я, арифметика; YouTube/ffmpeg: fps-фильтр лишь дублирует/отбрасывает кадры]. Для чистого результата — 60→30 (ровно каждый 2-й кадр) или 60→60.

### В2. Причины и лечение
1. **Несовпадение fps.** YouTube: «кодируйте и загружайте в той же частоте, в какой снято» (24, 25, 30, 48, 50, 60). [S] https://support.google.com/youtube/answer/1722171
   Фильтр fps/-r только дублирует/выкидывает кадры, новых движений не создаёт; для плавности — minterpolate (иногда «ghosty»). [S] https://www.creativeworksofknowledge.com/en/cwk-quests/ffmpeg-quest/conversions/lesson5/
   Правило [Я]: один выходной fps на проект. Кратные источники (60→30, 50→25, 25→25, 30→30) — децимация без артефактов. Некратные (24→30, 25→30, 60→25) дают неравные шаги/дубли кадров = рывки: либо держать родной fps на всех клипах, либо оптический поток (minterpolate mci / RIFE) на коротких кусках. Для этого проекта: основная масса исходников 25 fps → выход 25 fps, а 60-fps «машинку» сначала привести к 25 с blend (`framerate`-фильтр) или выбрать выход 30 fps (60→30 чисто, 25→30 даёт дубль каждого 5-го кадра) — решить A/B на глаз. Слоу-мо при 24/25 fps — только с оптическим потоком.
   VFR → CFR: `-vf fps=N -fps_mode cfr` (или `-vsync cfr`); 29.97 не округлять до 30 (дрейф звука) → `30000/1001`. [S] creativeworksofknowledge (выше)
2. **Целочисленные сдвиги кропа / ступенчатый зум.** ffmpeg `crop`: x,y считаются на каждый кадр, невалидные значения «приближаются к ближайшему валидному», без `exact=1` субдискретизованное видео округляется вниз (рывок 1–2 px на сдвиге) [S] https://ayosec.github.io/ffmpeg-filters-docs/8.1/Filters/Video/crop.html ; зум в `zoompan` тоже дрожит из-за округления (баг #4298, патч с субпиксельным масштабированием 2020/2025) [S] https://ffmpeg.org/pipermail/ffmpeg-devel/2020-January/256218.html , https://trac.ffmpeg.org/ticket/4298
   Лечение [Я]: двигать кроп в float, а целые пиксели получать только после суперсэмплинга: `scale` до 2× целевого размера → `crop` → downscale (эффективный шаг сдвига 0.5 px); либо считать кадры в Python/OpenCV `warpAffine` (субпиксель, INTER_LANCZOS4) и отправлять в ffmpeg через pipe. Чётная ширина кропа: `floor(srcH*9/16/2)*2`. [S, для чётности] https://github.com/xixihhhh/hotclip/blob/a09f89f1/src/core/reframe/track.ts
3. **Дрожащий трекинг лица (боксы шумят покадрово).** Не использовать бокс напрямую. AutoFlip: полиномиальная траектория и 3 режима (stationary/pan/tracking), сброс на смене шота. [S] research.google (А5). One Euro filter (Casiez 2012): адаптивный low-pass — при покое сильное сглаживание, при быстром движении мало задержки. [S] https://gery.casiez.net/1euro/ ; реализация в hotclip: DEAD_ZONE 0.02 (2% ширины), minCutoff 0.3, beta 0.007, dCutoff 1.0; STATIC если σ < 4% ширины → одна постоянная рамка по медиане («ноль дрожи = про-вид»); PAN если |дрейф| > 2σ → линейная интерполяция (до 12 шагов); иначе TRACK; если валидных детекций <40% (MIN_COVERAGE 0.4) → центр-кроп. [S] https://github.com/xixihhhh/hotclip/blob/a09f89f1/src/core/reframe/track.ts
   Рекомендация [Я]: по умолчанию статичный кроп на шот; трекинг только если лицо уходит >10–15% ширины кропа; ключи камеры — раз в ≥0.5 с с easing; скорость камеры ≤ ~1 ширина-кропа/с.
4. **Плохие ключевые кадры/GOP.** YouTube: closed GOP, длина GOP = половина fps (15 при 30 fps), 2 B-кадра подряд, High profile, CABAC, 4:2:0, BT.709, faststart (moov вперёд), VBR. [S] https://support.google.com/youtube/answer/1722171
5. **Низкий битрейт / мягкий источник.** YouTube SDR 1080p: 8 Мбит/с (24/25/30 fps), 12 Мбит/с (48/50/60). Выше ~10 Мбит/с для 1080×1920 выигрыш мал (YouTube всё равно пережимает в VP9/AV1). 4K-вертикаль на Shorts не улучшает (полка отдаёт 1080×1920). [S] https://www.ffmpeg-micro.com/blog/youtube-shorts-video-settings-that-survive-the-re-encode
6. **Ключевое правило эдитора:** в проекте один fps; все клипы приведены к нему до сборки; эффекты и зум применять на высоком разрешении, а ресайз — в конце (одним проходом). [Я]

### В3. Конкретные настройки x264 (30 fps; для 25 fps замените -g 12/13 → половина fps)
Источник параметров: YouTube Help + ffmpeg-micro (выше); CRF-вариант — мой [Я].
```
-vf "scale=1080:1920:flags=lanczos,fps=30,format=yuv420p,setsar=1"
-c:v libx264 -preset slow -profile:v high -level 4.0
-b:v 8M -maxrate 10M -bufsize 16M          # (60 fps: -b:v 12M, level 4.2, -g 30)
-g 15 -keyint_min 15 -sc_threshold 0 -bf 2 # closed GOP = fps/2
-color_primaries bt709 -color_trc bt709 -colorspace bt709
-c:a aac -ar 48000 -ac 2 -b:a 192k -af loudnorm=I=-14:TP=-1.5:LRA=11
-movflags +faststart -t 179
```
Вариант «по качеству» [Я]: вместо -b:v: `-crf 16 -maxrate 12M -bufsize 24M` (проверить, что файл ≥6–8 Мбит/с на динамичных сценах).
Для 25-fps проекта: `fps=25`, `-g 12 -keyint_min 12`, битрейт 8M.

### В4. YouTube Shorts (официально)
- До 3 минут (с 15.10.2024), квадрат или вертикаль → Short. [S] https://support.google.com/youtube/answer/10059070 ; https://www.vidulk.com/video-specs/youtube-shorts

## 10 главных выводов
1. Не клади 16:9-полосу (1080×608 = 31.6% высоты) по центру — это и есть «полу-шортс»; делай трекинг-кроп 9:16 или кроп 9:8 в панель ≥55% высоты.
2. Хук: сильнейшая реплика в первые 1–2 с, клип 12–35 с (до 45), конец на закрытой мысли/петля; «событие» на экране каждые 3–4 с, punch-in 110–120% не чаще раза в 8–12 с.
3. Отбор «сочного»: транскрипт-скоринг (хук без контекста, число/конфликт/смех, закрытая мысль, 15–45 с), громкость — лишь дополнительный сигнал; для слабых ИИ — чек-лист 0/1 из 6 пунктов.
4. Эдит: реплика героя 2–5 с (туториал — до ~9 с) → riser → дроп с вспышкой 0.25 с и hit → планы 0.4–1.0 с на кик/снейр (бит 1 = смена сцены), 15–30 клипов, 15–30 с.
5. Скорость: кривая ~10× → 0.5× → 1× с оптическим потоком (24/25 fps рвётся даже при −25%); эффекты умеренно (резкость, хроматика, шейк, глоу).
6. Звук: музыка −10 дБ под голосом (≈20–25 дБ относительно), мастер −14 LUFS, SFX последним шагом.
7. Лаги в ваших файлах (ffprobe): 60-fps «машинка» сводится к 25 fps (делитель 2.4 → неравные шаги 2/3 кадра); все превью 25 fps при 1.3–3.0 Мбит/с против 8 Мбит/с рекомендации.
8. Один fps на проект, кратная децимация (60→30), оптический поток вместо дубляжа кадров; VFR → CFR.
9. Трекинг: статичный кроп на шот по умолчанию, One Euro (minCutoff 0.3, beta 0.007) + dead-zone 2% + суперсэмплинг/субпиксельный сдвиг вместо целых px; чётная ширина кропа; при <40% детекций — центр-кроп.
10. Экспорт: 1080×1920, H.264 High, 8 Мбит/с (30 fps) maxrate 10M, closed GOP = fps/2, 2 B-кадра, BT.709, yuv420p, faststart, AAC 48 kHz.
