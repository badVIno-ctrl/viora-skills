# Migration 1.6.0 / traffic v3.3 -> 1.6.1 / traffic v3.4

Старый видео-контракт и команды render/qa не заменены. Schema plan 1/1.4 не менялась.
Добавлены рекламные маршруты, templates/advertising, campaign.schema.json и отдельный
sidecar campaign.json; не вкладывать его в старый монтажный план.

Новые команды ad-init/ad-check не публикуют и не используют сеть/API.
Проверка draft допускает незаполненные бизнес-данные, но никогда не даёт ready_for_launch.
launch проверяет полноту, допуск, самоотчётные evidence и хэш финального файла.
Это не юридическая экспертиза/проверка сайта и не автоматическая оценка креатива.

release-check: если есть campaign.json либо release.advertising=true, выполнить ad-check launch.
Отсутствие карточки для явно помеченной рекламы блокирует ready. Для старых нерекламных
каталогов поведение сохранено. Непомеченную рекламу без campaign код не определяет.
Для статичных объявлений использовать ad-check и визуальную проверку, не видео-release.
Новый renderer статичных изображений не добавлен; использовать доступную SVG/PNG сборку.

Изменённые эвристики в рекламном режиме: не требовать gameplay, Telegram, QR, петлю,
«часть 2» и фиксированные отступы по умолчанию. Учебные бренды/ссылки не подставлять.
Старые fallback AnimatedBanner сохранены для совместимости; новый агент задаёт текст явно.

Исходные tests не ослаблять ради зелёного отчёта. Отдельно сообщить исходные дефекты,
невыполненные проверки и реальные результаты регрессии. Прохождение кода не доказывает
поведение будущего ИИ и рекламную эффективность.

## Согласование платных API (v3.4)
Потенциально платные HTTP-запросы TTS OpenAI/ElevenLabs и генерации обложек OpenAI/Gemini
по умолчанию заблокированы, даже при наличии API-ключей. Получить разрешение на конкретный
объём/бюджет, затем установить SHORTS_ALLOW_PAID=1 только для этого задания и сбросить после.
Флаг не является счётчиком расходов и не разрешает публикацию/закупку трафика.
Кэш озвучки и локальная сборка обложек из кадров не требуют платного запроса.
Если API заблокирован, не объявлять генерацию успешной: использовать разрешённый fallback
или сообщить точный блокер. Согласование и лимиты записать в бриф/отчёт.

Шаблон видео-выпуска рекламы: schema/release.advertising.example.json (все ручные
подтверждения остаются false). Встроенная база v3.2 сохранена; рекламные точки входа
00/18 дополнены указателем на приоритетные правила v3.4, без отката старых исправлений.

В campaign offer_status не дублируется: единый источник - offer.source_status.
ready_for_launch вычисляется ad-check, не редактируется в карточке. Дополнительные
claims/rules/qa/authorization/final_artifact усиливают минимальную спецификацию PDF.
Для fixed_placement в payable_action записать договорённое размещение/учитываемый охват,
а в tracking - источник отчёта; это не обещание клика или продажи каждому зрителю.

Исправление, найденное полной регрессией v3.4: SRT-паддинг последней строки теперь
ограничен финальной длительностью ролика. to_srt получил необязательный duration,
старые вызовы совместимы. Само слово за пределом длительности отклоняется, не прячется
обрезкой хвоста. Видеорендер передаёт фактическую рассчитанную длительность экспорту.
