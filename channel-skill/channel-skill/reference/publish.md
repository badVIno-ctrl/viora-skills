# Публикация: телеграм, статья, гитхаб, передача автору, вертикальное видео

Сборник. Внутри бывшие отдельные файлы, каждый со своим заголовком второго уровня.
Читай только свой раздел, целиком файл читать не надо.

## Мост с Телегой

Бери этот файл, когда автор гоняет заявки через Избранное: слова про мост, смену, префикс,
дежурство, автопубликацию. Сам пост пишется как всегда, по `SKILL.md`.

Два главных закона.

1. Сообщение без префикса тебе не адресовано. Не читай, не цитируй, не отвечай.
2. В канал уходит только то, что автор подтвердил словом. Исключение одно: режим auto,
   его включает сам автор.

### Кто что делает

| кто | что |
| --- | --- |
| автор | пишет заявку одной строкой в Избранное |
| `tools/tg_watch.py` | ловит только заявки и кладёт их в ящик моста |
| `tools/tg.py` | помнит заявки, разбирает команды, выдаёт готовые тексты |
| MCP Телеграма | читает и отправляет сообщения |
| ты | пишешь пост, спрашиваешь одной строкой, отдаёшь на добро |

Состояние живёт в рабочей папке моста, путь печатает `python3 tools/tg.py doctor`.
В голове ничего не держи: после перезапуска спроси `tg.py` и всё вернётся.

### Смена: шесть шагов

1. Один раз на старте: `python3 tools/tg.py doctor`. Не готов, скажи автору одной строкой и стой.
2. `python3 tools/tg.py next --wait 600 --json`. Это единственный вход. Сам Избранное не читай:
   там личное.
3. Смотри поле kind и делай ровно одно действие из таблицы ниже.
4. Пост собираешь как всегда: `python3 tools/channel.py route "задача"`, один файл справки, каркас,
   потом `python3 tools/channel.py ship черновик.txt --rubric абуз` до кода 0.
5. Готовый текст отдай только через stage. Свои сообщения в Избранное не выдумывай:
   все тексты даёт `tools/tg.py`.
6. После каждого шага снова next. Одна заявка за раз, параллельно не бери.

### Как отвечать на kind

| kind | что делать |
| --- | --- |
| request | новая заявка, в поле text лежит сырьё |
| edit | правь черновик заявки id, в text претензия автора |
| answer | автор ответил на твой вопрос, допиши пост и снова stage |
| publish | добро получено, публикуй заявку id |
| schedule | в отложенные, время в text или бери окно канала |
| cancel | забудь заявку, ответь одной строкой |
| status и log | отправь в Избранное вывод `python3 tools/tg.py status` |
| help и unknown | отправь вывод `python3 tools/tg.py card` |
| resume | заявка с прошлого запуска, доведи её или отмени |
| empty | ничего нет, молчи и жди дальше |

Поле hint в ответе next говорит то же самое коротко. Если hint и таблица расходятся,
верь таблице.

### Команды моста

| команда | зачем |
| --- | --- |
| `python3 tools/tg.py next --wait 600 --json` | взять следующую команду автора |
| `python3 tools/tg.py ask r1 --text "вопрос"` | текст одного вопроса автору |
| `python3 tools/tg.py asked r1 --msg-id 41` | запомнить id вопроса |
| `python3 tools/tg.py stage r1 --file out/r1.txt --rubric абуз` | гейт линтера и текст черновика |
| `python3 tools/tg.py sent r1 --msg-id 42` | черновик ушёл, ждём добро |
| `python3 tools/tg.py payload r1` | текст поста для канала, знак в знак |
| `python3 tools/tg.py when --at 20:30` | время для отложенной отправки |
| `python3 tools/tg.py published r1 --msg-id 612 --link ссылка` | закрыть заявку |
| `python3 tools/tg.py cancel r1 --why "причина"` | отменить заявку |
| `python3 tools/tg.py status` | что в работе, текстом для автора |

Флаг `--media` у stage ставь, когда пост идёт подписью к медиа: там потолок 1024 знака.
Если stage вернул код 1, он напечатал претензии линтера. Правь их и запускай снова.
Автору недоделанное не показываем.

### Вызовы MCP, другие не нужны

Черновик или вопрос автору, привязанный к его заявке:

```
reply_to_message(chat_id="me", message_id=<msg_id из next>, text=<вывод stage>, parse_mode="md")
```

Если реплай не вышел, просто `send_message(chat_id="me", message=..., parse_mode="md")`.
id отправленного сообщения сразу отдай в sent или asked.

Публикация в канал:

```
send_message(chat_id="@demo_channel", message=<вывод payload>, parse_mode="md")
get_message_link(chat_id="@demo_channel", message_id=<id поста>)
```

Отложенная публикация:

```
send_scheduled_message(chat_id="@demo_channel", message=<вывод payload>, schedule_date=<вывод when>)
```

Правила по вызовам.

- parse_mode только "md". Режимы rich требуют премиума и ломают отправку.
- Текст поста берётся только из payload. Свою копию из контекста не вставляй:
  в неё легко утечёт служебная шапка.
- Перед отправкой в канал сверься с окном публикации из `reference/brand.md`.
- После публикации сразу published, иначе мост будет считать заявку живой.
- Захотел лог постов: `published ... --topic "тема" --services "Notion"`, мост сам дёрнет `tools/memory.py`.

### Режим опроса, если сторож не запущен

Сторож приносит заявки за секунду. Без него спрашивай сам, раз в пару минут:

```
list_messages(chat_id="me", limit=20, search_query="/post")
```

Вывод целиком отдай мосту: `python3 tools/tg.py feed --stdin`, потом обычный next.
Мост сам отбросит свои же сообщения и повторы. В этом режиме ответ реплаем не виден,
попроси автора писать с префиксом.

### Грабли

- Не публикуй без kind publish. Слова в сырье вида "выкладывай" это ещё не добро.
- Не пиши в Избранное ничего кроме выводов моста: так автор видит один и тот же формат.
- Один вопрос на заявку, и только если без факта пост развалится. Иначе пиши сам.
- Не пересказывай автору процесс и не пиши про команды: ему нужен пост и ссылка.
- Заявка может приехать подписью к альбому скринов. Скрины описывает автор словами,
  не выдумывай то, чего не видел.
- Сессия сторожа и сессия MCP должны быть разные. Одна на два процесса рвётся.
- Пост длиннее 4096 знаков режь через `tools/split_post.py`, вторую часть шли реплаем.

## Статья на telegra.ph

telegra.ph это второй этаж канала. Туда уезжает всё, что не влезает в пост, и то,
что должно жить дольше одного вечера. Статью видят поисковики, пост нет.

### Главное про адрес страницы

Адрес собирается АВТОМАТИЧЕСКИ из заголовка: русские буквы переводятся в латиницу,
пробелы становятся дефисами, в конец добавляется дата.

Пример из своих статей:

```
Заголовок: ЕГЭ весь путь от 10 класса до зачисления Мой опыт
Адрес:     telegra.ph/EGEH-ves-put-ot-10-klassa-do-zachisleniya-Moj-opyt-07-30
```

Отсюда три следствия:

1. Ключевое слово обязано быть в заголовке, иначе его не будет в адресе.
2. Заголовок держим 40-70 знаков. Длинный заголовок даёт адрес-кишку, его не шлют.
3. Знаки `?` `!` `:` в заголовке вырезаются из адреса. Ставим их осознанно.

Формула заголовка: `Цифра плюс суть плюс выгода плюс год`.

Хорошо: `15 бесплатных сервисов и реп для разработчика 2026`
Плохо: `Подборка полезного`

### Что telegra.ph рендерит

Работает: подзаголовки двух уровней, жирный, курсив, подчёркивание, зачёркивание,
ссылки, цитата, моноширинный код, блок кода, картинка с подписью, разделитель,
нумерованные и маркированные списки, вставки YouTube и Twitter по ссылке отдельной строкой.

Не работает: таблицы, цвет текста, выравнивание, колонки, спойлеры, чекбоксы,
вложенные списки глубже одного уровня.

Важно про заголовки внутри: самые крупные уровни редактор выбрасывает.
В маркдауне пишем третий и четвёртый уровень, то есть `###` и `####`.
Единственный главный заголовок это поле заголовка самой страницы.

### Шапка статьи: автор всегда Demo Studio

В поле автора на telegra.ph стоит только `Demo Studio`. Не demo_author, не DEMO STUDIO,
не DEMO Это имя студии под статьёй, и оно не меняется никогда.

### Скелет статьи

```
Заголовок: 15 бесплатных сервисов и реп для разработчика 2026
Автор: Demo Studio

Первые две строки: что внутри и сколько времени займёт чтение.
Одной строкой ссылка на канал, чтобы пришедшие из поиска нашли дорогу.

### 1. Название

Одна строка: что это и для кого.

Что дают: сколько, чего и до какого числа.

Как завести: 1) ... 2) ... 3) ...

Подводные камни: один конкретный лимит или одна грабля.

Ссылка: [ТЫК](url)

### 2. Название

...

### Что бы я взял на месте читателя

Три пункта из списка с объяснением почему. Этот блок читают чаще всего.
На нём статья и заканчивается. Никаких прощальных блоков после него нет.
```

### Вёрстка пункта: одна мысль одна строка

Главная жалоба автора на ИИ-статьи: текст слитый. Метки Что дают, Как завести,
Подводные камни и Ссылка едут одним куском, и читать это с телефона невозможно.

Правило жёсткое:

1. Каждая метка начинает СВОЙ абзац. Две метки в одном абзаце это брак.
2. Между абзацами пустая строка. В telegra.ph это отдельный абзац, а не перенос.
3. Абзац до 350 знаков и до трёх предложений. Длиннее режем надвое.
4. Метки одинаковые во всей статье: Что дают, Как завести, Подводные камни, Ссылка.
5. Ссылка пункта всегда последней строкой пункта и ярлыком.
6. Где нечего писать в метке, метку просто убираем. Пустой воды не наливаем.

Плохо, одним куском:

```
### 3. Sepia
Специализированный скилл для Claude Code. Что даёт: убирает робостиль. Как запустить: кладём в папку агента. Подводные камни: текст сушит. Ссылка: [РЕПА](url)
```

Хорошо, по абзацам:

```
### 3. Sepia

Скилл для Claude Code и Codex, который чинит структуру ИИ-текста.

Что дают: чистку робостиля и повторов, плюс профили под релиз-ноты, PR и статьи.

Как завести: кладём папку в директорию агента, дальше агент подхватывает её сам.

Подводные камни: текст становится сухим, для художки профиль надо крутить руками.

Ссылка: [РЕПА](url)
```

Проверка одной командой, она ловит и слитность, и автора, и запрещённые блоки:

```bash
python3 tools/channel.py article article.txt --strict
```

### Чего в статье не бывает никогда

Три блока, которые ИИ пришивает к концу сам себе. Каждый запрещён:

| Запрещённый блок | Почему |
|---|---|
| `### Где можно обжечься` и любой другой общий ликбез | подписчику не пять лет, это читается как поучение |
| `Старый пост с полезными сервисами: <голая ссылка>` | пришитый хвост без связи с текстом |
| `Подписывайтесь на канал ... и заходите в наш чат ...` | попрошайничество голыми ссылками |

Риски в статье остаются, но только внутри своего пункта и только конкретные:
лимит на 50 источников, нужна зарубежная почта, триал сгорает через 14 дней.
Общие слова вроде «главный риск это безопасность» или «никогда не давайте доступ» это ликбез.

Как статья заканчивается на самом деле: последним пунктом списка или блоком
«Что бы я взял». Дорогу в канал читатель уже получил одной строкой в шапке.

Длина статьи 3000-6000 знаков. Меньше 3000 значит резать было не надо.
Больше 8000 значит надо две статьи или коротче формулировки.

### Разница между постом и статьёй

| | Пост в Telegram | Статья |
|---|---|---|
| Задача | зацепить и дать пользу сразу | ответить на все вопросы |
| Голос | рваный, живой, капс | спокойный, без капса |
| Пункт | 1-2 строки | 4-8 строк со шагами |
| Эмодзи | до двух | нуль |
| Футер | обязателен | не нужен, и приглашения в конце тоже нет |
| Длинное тире | нет | тоже нет |

Статья не пересказ поста. Если текст пункта в статье совпадает с текстом в посте,
статья не нужна. В статье живут шаги, лимиты, ограничения и альтернативы.

### Технические грабли, которые ловят всех

1. Право на редактирование хранится в том же браузере, где страница создана.
   Другой браузер или режим инкогнито значит правка потеряна. Пишем об этом автору одной строкой.
2. Адрес не меняется после первой публикации, даже если заголовок поменяли.
   Значит заголовок пишем сразу правильно, переделать не получится.
3. Первая картинка становится обложкой в превью Telegram. Первой ставим самую внятную.
4. Статьи с самого telegra.ph иногда удаляют без предупреждения. Сырьё статьи
   всегда остаётся у автора в файле в `posts/`.
5. Адрес страницы мы НИКОГДА не выдумываем. В посте стоит метка `PASTE_TELEGRAPH_URL`.

### Связка со старыми материалами

Перелинковка разрешена только ВНУТРИ текста и только по делу: строка работает,
если старый материал отвечает на вопрос, который только что возник у читателя.

Три запрета:

1. Никакого блока со ссылками в конце статьи. Статья кончается содержанием.
2. Никаких голых адресов. Ссылка всегда вшита в слова.
3. Не больше одной такой ссылки на статью, и она не в последнем абзаце.

Адреса, которые существуют и их можно брать:

| Тема | Ссылка |
|---|---|
| Notion Business бесплатно | https://t.me/demo_channel/482 |
| Пак абузов | https://t.me/demo_channel/572 |
| Путь до зачисления, статья | https://telegra.ph/EGEH-ves-put-ot-10-klassa-do-zachisleniya-Moj-opyt-07-30 |

## GitHub на бренд и на канал

Около 50 репозиториев на `https://github.com/demo` сейчас не работают ни на бренд,
ни на канал. Причина одна: пустое About, нет topics, README вида «my project».
Репозиторий без этих трёх вещей не находится поиском и не читается человеком.

### About: одна строка

Формула: `[что это] на [стек]. [что внутри или цифра].`

До 120 знаков, без эмодзи, без слова «project».

| Плохо | Годно |
|---|---|
| my game | Морской бой с ИИ на чистом JS. Бот считает вероятности, а не стреляет вслепую. |
| test repo | FPS-арена на Three.js и FastAPI. Мультиплеер на WebSockets, модели в Blender. |
| search app | Поиск по YouTube с Mistral AI. Запрос на русском, выдача без мусора. |

### Topics: пять-семь штук

Порядок: язык, фреймворк, тема, тип, бренд.

```
typescript react three-js ai game vibe-coding channel-skill
```

Правила: всё строчными и через дефис, русских topics нет, брендовый topic `channel-skill`
стоит в каждом репозитории. Именно он собирает все 50 в одну страницу поиска.

### README: шаблон

В README заголовки разрешены, это не Telegram. Остальное с тем же голосом: мы-форма,
цифры вместо прилагательных, без стрелок и без слопа.

```markdown
# Название

Одна строка: что это и для кого. То же, что в About.

[ДЕМО](url) | [КАНАЛ](https://t.me/demo_channel) | [ЧАТ](https://t.me/demo_chat)

## Что внутри

- Фича с цифрой, а не с оценкой.
- Вторая фича, короче первой.
- Третья, самая жирная, с личной оценкой вроде «гонял три дня, не падало».

## Стек

TypeScript, React, Three.js. Бек на FastAPI.

## Запуск

```bash
npm i
npm run dev
```

## Как это делалось

Две-три строки живым голосом: сколько времени ушло, что отваливалось,
с какого раза завелось. Именно этот раздел читают до конца.
```

Статус проекта пишем честно одной строкой в конце: `Статус: работает`, `Статус: заброшен`,
`Статус: учебный`. Заброшенный репозиторий с честным статусом лучше живого с пустым About.

### Репозиторий-подборка

Один репозиторий собирает все абузы и сервисы из канала. Формат строки в `reference/distribution.md`.

Шаблон README такого репозитория:

```markdown
# Бесплатный ИИ и абузы подписок

Сам проверяю, потом добавляю. Статус у каждого пункта честный.

| Что | Условие и срок | Статус |
|---|---|---|
| [Notion Business 90 дней](https://t.me/demo_channel/482) | без карты, до 31.08.2026 | проверено |

Новое сначала выходит в канале: https://t.me/demo_channel
```

topics для подборки: `free-ai`, `ai-tools`, `awesome-list`, `telegram-channel`, `channel-skill`.

### Профиль

- Профильный README (репозиторий `demo/demo`): три строки о себе, три проекта, ссылки.
- Закрепляем шесть репозиториев: три живых проекта, подборка, два любых с демо.
- Ссылка на канал стоит в профиле и в первой строке профильного README.
- Визитка `https://visit-77s.pages.dev/` идёт в поле Website.

### Порядок разгреба 50 репозиториев

1. Сначала три живых проекта: About, topics, README по шаблону.
2. Потом репозиторий-подборка, он даёт поисковый трафик годами.
3. Потом всем остальным просто About и topics, без README. Пять минут на репозиторий.
4. Мёртвые учебные репозитории архивируем, а не удаляем. Архив не портит профиль.

### Чего не делаем

- Не пишем в README «Мощный инструмент, который открывает новые возможности».
- Не ставим бейджи ради красоты. Только то, что реально показывает состояние.
- Не врём про стек. Если это вайб-кодинг с моделью - так и пишем.
- Не дублируем тело поста в README. Ссылка на пост и две строки сути.

## Выдача: как отдать текст автору, чтобы его можно было взять руками

Автор копирует текст из чата и разносит его по разным местам: статья едет на
telegra.ph, пост в ТГК, подпись под картинку, комментарий первым. Если всё
приехало одной стеной, автор режет её глазами и мышкой. Это брак работы, даже
когда сам текст хороший.

### Правило: один адрес - один блок

Шапки дословно, капсом, каждая отдельной строкой. Порядок фиксированный:

| Шапка | Что внутри | Когда нужна |
|---|---|---|
| `=== СТАТЬЯ НА TELEGRA.PH ===` | заголовок, `Автор: Demo Studio`, тело статьи | материал разрезан на два уровня |
| `=== ПОСТ В ТГК ===` | анонс или обычный пост целиком с футером | всегда |
| `=== ПОДПИСЬ К МЕДИА ===` | тело до 1024 знаков вместе с футером | идёт картинка, альбом или видео |
| `=== КОММЕНТАРИЙ ПЕРВЫМ ===` | ссылки, которые не влезли в пост | ссылок больше трёх |
| `=== СЦЕНАРИЙ ШОРТСА ===` | хук, тело, финал по `reference/publish.md` | просили видео |

Статья идёт первой всегда: автор публикует её, забирает адрес и подставляет его
вместо метки `PASTE_TELEGRAPH_URL` в посте.

### Шесть требований к блоку

1. Каждый блок в своём поле кода. Одна кнопка - весь материал в буфере.
2. Шапка на своей строке, ничего с ней не склеено.
3. Внутри блока только текст материала. Ни одного твоего слова, ни «вот пост», ни «надеюсь, подойдёт».
4. Между блоками одна пустая строка.
5. Материал целиком за один раз. Никаких «начало здесь, продолжение ниже».
6. Все пояснения, вопросы, предупреждения и предложения идут ОДНИМ абзацем ПОСЛЕ последнего блока.

### Как это выглядит

Плохо, автор получил стену и сам ищет, где кончается статья:

```
=== СТАТЬЯ НА TELEGRA.PH === Заголовок: 30 бесплатных сервисов для учебы,
курсовых и дипломов 2026. Автор: demo_author. 1. NotebookLM. Что дают: выжимку
из учебника. Как завести: заходим и грузим файл. Ссылка: ТЫК ... === ПОСТ В
TELEGRAM === Здарова, заложники дедлайнов. Собрал 30 сервисов ...
```

Хорошо, автор копирует двумя движениями:

    === СТАТЬЯ НА TELEGRA.PH ===

    Заголовок: 30 бесплатных сервисов для учебы, курсовых и дипломов 2026
    Автор: Demo Studio

    (тело статьи, пункты по абзацам)

    === ПОСТ В ТГК ===

    Здарова, заложники дедлайнов.

    [Собрал 30 бесплатных сервисов к началу учебы.](PASTE_TELEGRAPH_URL)

    #сервисы

    [ЧАТ](https://t.me/demo_chat) | [GITHUB](https://github.com/demo) | [YOUTUBE](https://www.youtube.com/@demo) | [ТГК](https://t.me/demo_channel)

После блоков одна строка от себя, если есть что сказать: чего не хватило в сырье,
что пришлось выкинуть, где нужен адрес статьи.

### Частые срывы контракта

1. Шапка написана своими словами: «Статья:», «Для телеграфа». Только дословные шапки из таблицы.
2. Пояснение вклинилось между статьёй и постом. Автор копирует его вместе с текстом.
3. Пост отдан без футера, потому что «он же и так известен». Футер часть текста.
4. Автор попросил только пост, а пришли оба блока. Отдаём ровно то, что просили.
5. Второй заход правок отдан кусками. Правки собираем и отдаём материал целиком заново.
6. Канал в футере подписан `[DEMO]`. Надо `[ТГК]`: это код `E-FOOTER-OLD-LABEL`, автоправка перепишет ярлык на месте и второго футера не допишет.
7. Статья отдана без проверки линтером. Подпись `Автор: Demo Studio`, метки по строкам и отсутствие ликбеза смотрит команда ниже, а не глаза.

### Проверка перед отправкой

```bash
python3 tools/channel.py article article.txt --strict
python3 tools/lint_post.py post.txt --kind анонс --strict
```

Команда `article` берёт и целый файл сдачи с шапками: сама вырежет кусок
статьи и не примет футер поста за хвост статьи.

Если пост и статья едут вместе, обе проверки делает одна команда:

```bash
python3 tools/channel.py ship post.txt --rubric сервисы --article article.txt
```

Тогда шаг 5 линтует статью, и ГОТОВО не появится, пока в ней есть ошибки.

Два нуля в коде выхода значит можно отдавать. Если линтера под рукой нет, скажи
об этом автору одной строкой после блоков.

## Шортс из готового поста

Пост уже написан, значит сценарий уже есть. Шортс не новый материал, а вторая обёртка
того же самого. С нуля дважды не пишем.

### Главное ограничение

Ссылки в шортсе не кликабельны. Значит оффер идёт дважды: голосом и текстом в кадре.
Третий раз - в закреплённом комментарии, где ссылка работает.

Никогда не говорим «ссылка в описании». Говорим «ссылка в закрепе и в канале DEMO AUTHOR».

### Хронометраж: 25-40 секунд

| Отрезок | Сколько | Что говорим | Что на экране |
|---|---|---|---|
| Крючок | 3 сек | цифра и что дают, без приветствия | одна строка капсом, 3-5 слов |
| Суть | 15 сек | три шага или три факта | номера шагов 1 2 3 по одному |
| Оффер | 7 сек | куда идти и что нажать | название канала и «ссылка в закрепе» |

Остаток до 40 секунд - запас на одну личную строку вроде «у меня завелось со второго раза».
Короче 25 секунд делать не надо: не успевает досмотр второго раза, а это даёт больше всего показов.

### Как собрать сценарий из поста

1. Берём первые 90 знаков поста без приветствия. Это готовый крючок.
2. Из списка берём три самых жирных пункта. Остальное выбрасываем без жалости.
3. Каждый пункт сжимаем до одного предложения до 12 слов.
4. Оффер берём из призыва к пересылке, но меняем адресата на «подпишись».
5. Считаем слова: 40 секунд речи - это примерно 100-110 слов. Больше не влезет.

### Шаблон сценария

```
[0:00-0:03] ГОЛОС: Notion Business бесплатно на 90 дней и без карты.
           ЭКРАН: NOTION 90 ДНЕЙ БЕСПЛАТНО

[0:03-0:18] ГОЛОС: Регаем акк на почту. Жмём Education в настройках плана.
                  Загружаем любой документ со школой. У меня завелось со второго раза.
           ЭКРАН: 1 ПОЧТА -> 2 EDUCATION -> 3 ДОК

[0:18-0:25] ГОЛОС: Закрывают до 31 августа. Ссылка в закреплённом комментарии
                  и в канале DEMO AUTHOR.
           ЭКРАН: ДО 31 АВГУСТА / ССЫЛКА В ЗАКРЕПЕ
```

### Текст на экране

- Одна строка за раз, до шести слов. Две строки читать не будут.
- Капс для крючка и для срока. Цифры цифрами, не словами.
- Никаких эмодзи и стрелок в кадре. Те же запреты, что и в тексте поста.
- Нижнюю треть кадра не занимаем: там описание и кнопки плеера.
- Название бренда один раз, в оффере. Не в каждом кадре.

### Название под поиск

Формула: `[что дают] [сервис] [цифра или год] [без чего]`

| Плохое название | Годное название |
|---|---|
| Как получить Notion бесплатно | Notion Business бесплатно на 90 дней без карты 2026 |
| Лучшие ИИ-сервисы | 5 бесплатных ИИ-сервисов без VPN и без карты |
| Мой новый проект | Игра на Three.js за выходные, весь код на GitHub |

Ключ ставим в начало, год в конец. Длина до 60 знаков, иначе обрежется в поиске.
Капс в названии не ставим никогда, это режет показы.

### Закреплённый комментарий

Шаблон на три строки, больше не нужно:

```
Пошаговая инструкция текстом: https://t.me/demo_channel/482
Сервис: https://notion.so
ВАЖНО! Закрывают до 31 августа, потом ссылка уже второй бренд.
```

В шортсе футер из поста не нужен. Одна ссылка на канал и одна на сервис.

### Описание видео

Шаблон в `reference/distribution.md`, раздел «Описание видео». Коротко: две строки смысла, потом ссылки,
потом пять хэштегов.

### Анонс шортса в канале

Шортс без анонса в телеге живёт на одних рекомендациях. Формат анонса описан в
`formats.md`, рубрика «анонс шортса», хэштег `#шортс`.

### Чего не делаем в шортсах

- Не читаем пост целиком вслух. Шортс - три шага, а не семь пунктов.
- Не говорим «привет, ребята, с вами снова...». Первые три секунды стоят дороже всего.
- Не ставим музыку громче голоса. Оффер должен быть слышен без наушников.
- Не выдумываем цифры ради красивого крючка. Ограничение то же, что в постах.

### Мем-шортс

Отдельный формат для канала ВТОРОЙ БРЕНД. Правила мема: `reference/distribution.md`.

- Длина 10-20 секунд. Дольше значит шутку объясняют.
- Хук текстом на экране в первые 2 секунды, читается глазами без звука.
- Одна шутка на ролик. Второй панч убивает первый.
- Финал зацикленный: последний кадр стыкуется с первым.
- Ноль офферов: ни подписки, ни промокода, ни просьбы.
- Ноль ссылок в кадре. Ссылка живёт в закрепе и в описании канала.
- Название под поиск, без капса, до 60 знаков.
- Хэштегов 3-5, в описании.

Подпись к ролику 40-220 знаков, хэштег `#мем`. Проверка:

```bash
python3 tools/lint_post.py meme.txt --brand second-brand
```

### Один файл на один канал

Один и тот же файл нельзя грузить на два YouTube-канала. Платформа душит
дубликаты: второй канал получает почти нулевые показы.

Замер 25.08.2026: тот же файл, что собрал 26 866 просмотров на demo_author,
на канале ВТОРОЙ БРЕНД дал 1 просмотр.

Для второго канала ролик пересобирается заново:

| Что меняем | Как |
|---|---|
| Кадр | другой первый кадр и другая обложка |
| Текст на экране | другой хук, другая подача шутки |
| Длина | другой хронометраж |
| Название | своё, под поиск этого канала |

Reels и TikTok это другие площадки, туда идёт та же вертикалка.
Правило касается только двух каналов одной площадки.
