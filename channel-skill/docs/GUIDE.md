# Документация channel-skill

Один файл вместо восьми. Содержание ниже, каждый раздел читается отдельно.

- Быстрый старт
- Как устроен скилл
- Профиль автора: все поля
- Профиль автора
- Настройка под свой канал
- Подключение Телеграма: свои ключи, свой канал

- Безопасность и приватность

## Быстрый старт

Цель: первый готовый пост за три минуты. Без платных ключей и без настроек Телеграма.

### Шаг 1. Забрать скилл

```bash
git clone https://github.com/OWNER/channel-skill.git
cd channel-skill
python3 --version   # нужна 3.8 или выше
```

Если скачал архивом, распакуй и зайди в папку с файлом `README.md`.

### Шаг 2. Пройти интервью

```bash
cd channel-skill
python3 tools/onboard.py
```

Пять коротких блоков вопросов: кто ты, о чём и для кого, куда выходит и какие ссылки,
ритм и масштаб, рубрики и публикация. Обязательных ответов всего пять:
имя канала, ник автора, темы, аудитория, тон. Остальное можно пропустить и добавить потом.

Агенту удобнее спросить в чате:

```bash
python3 tools/onboard.py --questions        # отдаёт вопросы в JSON
python3 tools/onboard.py --stdin < ans.json # принимает ответы одним JSON
```

Самый быстрый путь: взять готовый шаблон из папки profiles и поменять поля руками:

```bash
cp profile/profiles/ru-tech-telegram.json profile/profile.json
python3 tools/onboard.py --render
```

### Шаг 3. Проверить профиль

```bash
python3 tools/profile.py --check   # должно быть: Профиль на месте
python3 tools/profile.py --show    # посмотреть карточку канала
python3 tools/profile.py --footer  # увидеть свой футер знак в знак
```

Если видишь предупреждение про демо-профиль, значит интервью не пройдено и скилл работает
на демо-данных DEMO STUDIO. В таком виде посты в свой канал ставить нельзя.

### Шаг 4. Попросить пост

Скажи агенту обычными словами:

```
Сделай пост про новый инструмент для монтажа, рубрика гайд
```

Агент сам поймёт рубрику и каркас. Если сомневается, пусть спросит маршрутизатор:

```bash
python3 tools/channel.py route "нужен пост про новый инструмент"
```

### Шаг 5. Проверить черновик

```bash
python3 tools/channel.py ship draft.txt --rubric гайд
```

Одна команда делает четыре вещи: механическая автоправка, линтер поста, оценка по
цифрам твоего канала и проверка разреза. По отдельности:

```bash
python3 tools/lint_post.py draft.txt --strict
python3 tools/score_post.py draft.txt --rubric гайд
python3 tools/split_post.py draft.txt --check
```

### Шаг 6. Публикация

Публикует автор. Скилл отдаёт текст и говорит, что исправить. Если хочешь доставлять
задачи и черновики через своё Избранное в Телеграме, собери мост: [TELEGRAM.md](TELEGRAM.md).

### Если что-то не так

| Симптом | Что делать |
| --- | --- |
| Агент пишет чужим голосом | `python3 tools/profile.py --check`, проверь brand.tone и brand.audience |
| В тексте длинные тире | `python3 tools/lint_chat.py --text "строка"` и правило ноль в `SKILL.md` |
| Футер не тот | `python3 tools/profile.py --footer`, потом `python3 tools/onboard.py --render` |
| Сломался один из скриптов | `bash tools/check_all.sh` и читать первую красную строку |
| Надо начать с нуля | `python3 tools/onboard.py --force` |

Дальше: [PROFILE.md](PROFILE.md) про все поля, [CUSTOMIZE.md](CUSTOMIZE.md) про свои рубрики,
[ARCHITECTURE.md](ARCHITECTURE.md) про устройство.

## Как устроен скилл

Коротко: один источник правды про автора, один источник правды про правила,
детерминированные проверки поверх. Модель пишет, скрипты судят, человек публикует.

### Цепочка данных

```
интервью (tools/onboard.py)
        ↓
профиль автора (profile/, JSON по схеме)
        ↓
читалка профиля (tools/profile.py)
        ↓
───┬──────────┬───────────┬─────────────┬───────────────
   тексты     линтеры      оценка        мост с Телеграмом
  (reference/) (lint_*.py)  (score_post.py)   (tg.py, tg_watch.py)
        ↓
готовый черновик → автор нажимает публикацию
```

### Три слоя

#### 1. Профиль: кто пишет

Всё, что зависит от конкретного автора, лежит в одном JSON: имя, тон, темы, аудитория,
ссылки, рубрики, цифры канала, настройки Телеграма. Скрипты не знают ниодного имени
напрямую: они спрашивают `tools/profile.py`.

Файлы слоя: `tools/onboard.py` собирает, `tools/profile.py` читает и валидирует,
`profile/profile.schema.json` описывает структуру, `profile/profile.example.json` даёт демо-данные,
чтобы скилл запускался сразу после распаковки.

Почему так: без этого слоя скилл был бы привязан к одному каналу. Разделение позволяет
отдать его любому автору и не менять ни строки кода.

#### 2. Знание: как писать

Текстовые правила лежат в справочниках: голос, крючок, вёрстка, разрез, борьба с ИИ-признаками,
форматы, рост, SEO. Порядок чтения задаёт `ROUTER.md`: на одну задачу один файл, не больше.

Три тира на разные модели:

| Тир | Что читает | Кому |
| --- | --- | --- |
| Карточка | `QUICKCARD.txt` | быстрые и слабые модели |
| Правила | `SKILL.md` плюс один справочник | рабочая норма |
| Полный | `PROMPT-FULL.txt` | аудит и спорные случаи |

Промпты не пишутся руками дважды. `tools/build_prompt.py` собирает `PROMPT-CORE.txt` и
`PROMPT-FULL.txt` из помеченных блоков в исходных файлах, а `--check` падает, если копия
разошлась с источником.

#### 3. Проверки: что считается готовым

Субъективные оценки плохо работают, поэтому всё проверяемое проверяют скрипты:

| Скрипт | За что отвечает |
| --- | --- |
| `tools/lint_post.py` | футер, ссылки, хэштеги, запретные символы и штампы |
| `tools/lint_article.py` | статья на telegra.ph: заголовок, длина, подпись |
| `tools/lint_chat.py` | ответ агента в чате, тот же запрет на длинные тире |
| `tools/score_post.py` | балл по коридорам рубрики и цифрам канала |
| `tools/split_post.py` | разрез на пост и статью, лимиты Телеграма |
| `tools/validate_skill.py` | целостность самого скилла: версии, ссылки, футеры |
| `tools/run_evals.py` | эталоны поведения из `evals/cases.json` |
| `tools/check_all.sh` | всё выше одной командой |

У каждого скрипта есть свой самотест: `python3 tools/lint_post.py --selftest`. Самотесты не требуют
сети и не читают живой профиль: они специально переключаются на демо-данные,
чтобы результат не зависел от того, кто запустил.

### Мост с Телеграмом

`tools/tg.py` это одноразовые команды (вход, диагностика, отправка, статус),
`tools/tg_watch.py` это сторож, который смотрит твоё Избранное и ставит задачи в очередь.
Режим по умолчанию draft: ничего не улетает в канал без человека.
Ключи и строка сессии берутся из переменных среды или из папки secrets, в гит они не попадают.

### Память канала

Папка memory держит то, что нельзя вывести из профиля: уже использованные приветствия,
прошлые темы, принятые решения, фактические цифры по постам. `tools/memory.py` проверяет
приветствие на повтор и ведёт журнал.

### Поставка

`tools/install.py` кладёт копию скилла в папки обнаружения чужого проекта,
`tools/package.py` собирает архив для раздачи и проверяет состав через `--check`.

### Решения и причины

| Решение | Почему |
| --- | --- |
| Нуль внешних зависимостей в ядре | скилл должен запускаться сразу, без pip |
| Профиль в JSON, а не в коде | автор правит свои данные без страха сломать логику |
| Правила в тексте, проверки в коде | модель читает текст, но судит детерминизм |
| Один файл на задачу | больше контекста не значит лучше текст |
| Режим draft по умолчанию | публикация это ответственность человека |
| Запрет на длинное тире | самый заметный след модели, дешёво ловится машиной |

Дальше: [CUSTOMIZE.md](CUSTOMIZE.md) про перенастройку, [PROFILE.md](PROFILE.md) про поля профиля.

## Профиль автора: все поля

Профиль главный файл всего скилла. Имя автора, имя канала, голос, рубрики, коридоры длины,
футер и цифры канала живут здесь, а не в текстах скилла. Поменял профиль, поменялся весь скилл.

Где лежит: `channel-skill/profile/profile.json`. Этого файла нет в репозитории и он в .gitignore:
у каждого автора он свой.

Собрать его руками не надо. Пройди интервью:

```bash
cd channel-skill
python3 tools/onboard.py
```

Этот файл нужен, когда хочется поправить одно поле руками или понять, на что оно влияет.

### Три команды на всю жизнь

```bash
python3 tools/profile.py --show    # карточка профиля человечески
python3 tools/profile.py --check   # проверка полей и понятные ошибки
python3 tools/profile.py --who     # одна строка: кто автор и какой канал
```

Ещё есть `--json`, `--footer`, `--path` и `--selftest`.

### Как устроен файл

Обычный JSON в UTF-8. Полей много, но обязательных мало: всё остальное берётся из умолчаний.
Готовый пример целиком: `profile/profile.example.json`.
Формальная схема для редактора: `profile/profile.schema.json`.

Два шаблона на старт: `profile/profiles/ru-tech-telegram.json` и `profile/profiles/en-creator-telegram.json`.

### brand: кто ты

| Поле | Тип | Зачем |
| --- | --- | --- |
| `name` | строка, обязательно | Имя канала или бренда. Видно в подписях и в служебных сообщениях |
| `short` | строка | Короткое имя для тесных мест. Нет, возьмётся первое слово из name |
| `author` | строка, обязательно | Ник или имя. Скилл пишет от этого человека |
| `language` | ru, en и так далее | Язык постов. По умолчанию ru |
| `tone` | строка, обязательно | Голос в трёх словах, например нашёл, проверил, принёс |
| `audience` | строка, обязательно | Для кого пишем и в какой обстановке читают |
| `topics` | список строк | Темы канала. Из них собираются идеи и проверка на оффтоп |
| `about` | строка | Чем автор занимается. Даёт живые детали в тексте |
| `taboo` | список строк | Темы, которые не трогаем никогда |

### channel: куда выходит текст

| Поле | Тип | Зачем |
| --- | --- | --- |
| `platform` | telegram или other | Пока все форматы заточены под телеграм |
| `handle` | `@имя_канала` | Проверяется шаблоном: латиница, цифры и подчёркивание, 4-32 знака |
| `url` | ссылка | Полный адрес канала. Пусто, соберётся из handle |
| `window` | `16:30-21:00` | Окно публикации. Скилл предлагает время внутри этого окна |
| `tz` | зона IANA | Например Europe/Moscow или Europe/Berlin |

### links и footer: подвал поста

`links` это список пар в том порядке, в каком они стоят в футере:

```json
"links": [
  {"label": "ЧАТ", "url": "https://t.me/your_chat"},
  {"label": "GITHUB", "url": "https://github.com/your-name"}
]
```

Ярлык капсом и до 12 знаков. Ссылка обязана начинаться с http или https.

| Поле | Тип | Зачем |
| --- | --- | --- |
| `footer.enabled` | true или false | Нужен ли футер вообще |
| `footer.template` | строка | Свой футер знак в знак. Пусто, соберётся из links |
| `footer.legacy_labels` | список строк | Старые ярлыки вроде `[V.S.](`. Линтер ловит их в старых черновиках |

Проверить, как выглядит футер: `python3 tools/profile.py --footer`.

### article: длинный текст

| Поле | Тип | Зачем |
| --- | --- | --- |
| `article.enabled` | true или false | Разрешать ли связку пост плюс статья |
| `article.platform` | строка | По умолчанию telegra.ph |
| `article.signature` | строка | Подпись в конце статьи |

### second_brand: вторая площадка

Отдельный мемный или лёгкий канал того же автора. Подробности в `reference/distribution.md`.

| Поле | Тип | Зачем |
| --- | --- | --- |
| `second_brand.enabled` | true или false | Выключено, рубрика просто не появляется |
| `second_brand.name` | строка | Имя второй площадки |
| `second_brand.tag` | строка | Какая рубрика её обслуживает, например мем |
| `second_brand.min` и `max` | числа | Коридор длины подписи |
| `second_brand.footer` | true или false | Нужен ли там обычный футер |

### rubrics: только отличия от умолчаний

В скилле есть готовый набор рубрик с каркасами и коридорами. В профиле пишем только то,
что отличается. Пустой объект значит взять всё как есть.

```json
"rubrics": {
  "гайд": {"min": 900, "max": 1800},
  "реклама": null,
  "обзор": {"min": 400, "max": 800, "points": [3, 5], "frame": "PAS"}
}
```

- Объект с полями накладывается поверх умолчания.
- `null`, `false`, `"off"` или `"нет"` выключают рубрику насовсем.
- Новое имя создаёт свою рубрику.

Поля строки рубрики: `min`, `max` (коридор знаков), `points` (сколько пунктов в теле),
`frame` и `frame_alt` (каркасы вроде AIDA или PAS), `forward` (required, wanted или none),
`file` (какой файл из reference читать), `soft_first_screen` (мягкий первый экран).

Свой итоговый набор всегда виден в `python3 tools/profile.py --show`.

### voice: добавки к голосу

| Поле | Тип | Зачем |
| --- | --- | --- |
| `voice.greeting_max_words` | число | Потолок слов в приветствии, по умолчанию 5 |
| `voice.extra_banned` | список слов | Личный стоп-лист сверх общего |
| `voice.extra_lexicon` | список слов | Свои словечки, которые линтер не трогает |

### metrics: цифры канала

```json
"metrics": {"subscribers": 260, "reach": [165, 386], "reactions": [1, 5]}
```

Оценка поста считается от этих чисел, а не от чужих. Если канал только стартует, ставь нули:
скилл просто не будет ссылаться на охват.

### telegram: мост с Избранным

| Поле | Тип | Зачем |
| --- | --- | --- |
| `telegram.prefixes` | список строк | Команды в Избранном, на которые отвечает сторож |
| `telegram.mode` | draft, scheduled или auto | Что делать с готовым текстом |
| `telegram.inbox` | строка | Куда класть черновик, по умолчанию me |

Ключи и сессия в профиле не хранятся никогда. Они живут в `secrets/telegram.env`,
а подключение описано в `docs/GUIDE.md`.

### Частые ошибки проверки

| Что говорит --check | Что делать |
| --- | --- |
| нет brand.name, brand.author, brand.tone или brand.audience | Заполнить: без этого голоса нет |
| channel.handle должен быть вида @имя_канала | Убрать ссылку целиком, оставить хэндл |
| channel.window должен быть вида 16:30-21:00 | Два времени через дефис |
| ярлык ссылки не годится | Капс, до 12 знаков, без эмодзи |
| футер включён, но ссылок нет | Заполнить links или footer.template |
| в профиле длинное тире | Заменить на обычный дефис |
| не осталось ни одной рубрики | Вернуть хотя бы одну |
| коридор знаков задан наоборот | min меньше max |
| telegram.mode должен быть draft, scheduled или auto | Починить значение |

### Как поменять профиль позже

Переименовался, сменил тему, добавил ссылку:

```bash
cd channel-skill
python3 tools/onboard.py --force    # пройти интервью заново
python3 tools/onboard.py --render   # просто пересобрать тексты под новый профиль
```

`--render` нужен всегда, когда правишь JSON руками: он разносит новые данные
по карточке, справочникам и памяти канала.

## Профиль автора

Здесь живёт вся личная часть скилла: имя бренда, голос, рубрики, ссылки,
окно выхода, цифры канала. Инструменты читают профиль и подстраиваются
сами: в коде нет ни одного чужого бренда.

### Файлы

| Файл | Зачем |
| --- | --- |
| `profile.example.json` | демо-профиль поставки, чтобы скилл работал сразу |
| `profile.schema.json` | схема полей для редактора и проверки |
| `profiles/` | готовые шаблоны под типичные каналы |
| profile.json | твой профиль. Собирается интервью, в гит не попадает |

Демо-профиль нужен только для тестов и первого знакомства. Публиковать посты
с его ссылками нельзя: они вымышленные.

### Как завести свой профиль

Самый короткий путь: попроси модель провести интервью. Порядок вопросов
и правила описаны в `ONBOARDING.md`.

В терминале:

```
python3 tools/onboard.py               # интервью вопрос за вопросом
python3 tools/onboard.py --check       # код 1, если профиля нет или он демовый
python3 tools/profile.py --show        # что сейчас в профиле
python3 tools/onboard.py --render      # применить правки ко всем текстам
```

Готовые шаблоны:

```
python3 tools/onboard.py --from-json profile/profiles/ru-tech-telegram.json
python3 tools/onboard.py --from-json profile/profiles/en-creator-telegram.json
```

Поверх готового профиля пишет только `--force`.

### Поля, которые важнее всего

- `brand.name`, `brand.author`: имя канала и подпись автора.
- `brand.tone`: три глагола про то, что ты делаешь. Из них растёт голос.
- `brand.audience`: для кого пишешь и в какой обстановке читают.
- `brand.taboo`: темы, которые скилл обязан обходить.
- `channel.handle`, `channel.window`, `channel.tz`: куда и когда выходит.
- `links` и `footer.enabled`: хвост поста. Футер можно выключить совсем.
- `rubrics`: коридоры знаков и рамки по рубрикам.
- `metrics`: подписчики и охваты, нужны для трезвой оценки поста.
- `telegram`: префиксы заявок и режим публикации: `draft`, `scheduled`, `auto`.

### Рубрики

Значения по умолчанию уже есть: в `rubrics` лежат только правки.

```json
"rubrics": {
  "гайд": {"min": 900, "max": 2000},
  "реклама": null,
  "обзор": {
    "min": 400,
    "max": 800,
    "points": [3, 5],
    "forward": "required",
    "frame": "SLAY",
    "frame_alt": "BAB",
    "file": "reference/formats.md"
  }
}
```

- `null` убирает рубрику совсем;
- `min` и `max` задают коридор знаков;
- `points` сколько пунктов ждём в теле;
- `forward` одно из `required`, `wanted`, `none`;
- `frame` и `frame_alt` рамки подачи: SLAY, PAS, AIDA, BAB, STAR;
- `file` куда скилл идёт за образцами.

После любой ручной правки вызови проверку и пересборку:

```
python3 tools/profile.py --check
python3 tools/onboard.py --render
```

## Настройка под свой канал

Всё, что касается твоего канала, меняется в профиле. Код править не надо.
После любой правки прогони две команды:

```bash
cd channel-skill
python3 tools/profile.py --check
python3 tools/onboard.py --render
```

Первая проверяет профиль, вторая разносит новые данные по текстам скилла
и пересобирает промпты.

### Свои рубрики

В скилле есть готовый набор рубрик с каркасами и коридорами длины. В профиле ты его правишь
точечно, а не переписываешь целиком:

```json
{
  "rubrics": {
    "гайд": { "min": 700, "max": 1500 },
    "реклама": null,
    "опрос": { "points": [1, 3] }
  }
}
```

- объект с полями перекрывает только указанные поля;
- `null` или слово нет выключает рубрику совсем;
- хотя бы одна рубрика должна остаться, иначе проверка ругается.

Посмотреть, что получилось:

```bash
python3 tools/profile.py --show
python3 tools/channel.py route "нужен пост про новый инструмент"
```

### Свой голос

Блок voice в профиле:

```json
{
  "voice": {
    "greeting_max_words": 4,
    "extra_banned": ["друзья", "коллеги", "в современном мире"],
    "extra_lexicon": ["сборка", "пресет", "таймлайн"]
  }
}
```

- `greeting_max_words` ограничивает длину первой строки поста;
- `extra_banned` добавляет свои стоп-слова к общему списку штампов;
- `extra_lexicon` это твои слова, которые скилл старается использовать.

Проверка приветствия на повтор:

```bash
python3 tools/memory.py check-greeting "первая строка поста"
```

### Свой футер

По умолчанию футер собирается из списка links в том же порядке. Если хочешь свою строку
знак в знак, задай `footer.template`. Проверить результат:

```bash
python3 tools/profile.py --footer
```

Старые подвалы из архивных постов перечисли в `footer.legacy_labels`: линтер будет ловить их
как ошибку, если модель вспомнит старый вариант.

### Второй бренд или мемный подканал

```json
{
  "second_brand": {
    "enabled": true,
    "name": "МЕМ ОТДЕЛ",
    "tag": "второй",
    "min": 40,
    "max": 220,
    "footer": false
  }
}
```

Правила голоса и шаблоны коротких шуток лежат в `reference/distribution.md`.
Когда `enabled` выключен, рубрика исчезает из маршрутов и не мешает.

### Свои цифры для оценки

```json
{
  "metrics": { "subscribers": 1200, "reach": [400, 900], "reactions": [3, 12] }
}
```

Оценка сравнивает черновик с твоими реальными вилками, а не со средним по рынку.
Заниженные цифры делают оценку бессмысленной, поэтому бери данные из статистики канала.

### Другой язык

Поставь `brand.language` в en, es или другой код и сделай свои рубрики с латинскими именами,
а русские отключи через `null`. Готовый пример лежит в `profile/profiles/en-creator-telegram.json`.
Справочники остаются на русском: это инструкции для модели, не для читателя.

### Свои правила и свои файлы

1. Добавь файл в папку reference и опиши в нём один сюжет.
2. Пропиши строку в `ROUTER.md`, чтобы агент знал, когда его читать.
3. Если правило важно всегда, заверни его в блок CORE и пересобери промпты:

```bash
python3 tools/build_prompt.py
python3 tools/build_prompt.py --check
```

4. Проверь целостность скилла и эталоны:

```bash
python3 tools/validate_skill.py --root ..
python3 tools/run_evals.py
```

Новые проверки поведения добавляются в `evals/cases.json`.

### Чего лучше не делать

- Не вписывать имя канала и ссылки в код скриптов: сломается при обновлении.
- Не править `PROMPT-CORE.txt` и `PROMPT-FULL.txt` руками: они собираются из источников.
- Не добавлять длинные тире ни в профиль, ни в свои файлы: проверка упадёт.
- Не хранить ключи в профиле: им место в папке secrets или в переменных среды.

## Подключение Телеграма: свои ключи, свой канал

Мост с Телеграмом необязателен. Скилл пишет посты и без него: готовый
текст можно скопировать руками. Мост нужен, если хочется управлять
всем из Избранного: кинул тему себе в чат, получил черновик, одобрил,
пост ушёл в канал в твоё окно выхода.

В поставке нет ни одного чужого ключа. Каждый автор подключает свой
аккаунт и свой канал.

### Шаг 1. Свои ключи

1. Открой my.telegram.org и войди по номеру.
2. Раздел API development tools, создай приложение с любым именем.
3. Забери два значения: `api_id` и `api_hash`.

Это личные данные, один раз на аккаунт. В чат модели их не несут.

### Шаг 2. Файл с ключами

```
cp secrets/telegram.env.example secrets/telegram.env
```

Открой копию и вставь свои значения. Файлы `secrets/*.env` закрыты
в `.gitignore`: в гит они не попадут. Если держишь секреты в другом месте:

```
export CHANNEL_SECRETS=/путь/к/папке
```

### Шаг 3. Вход

```
python3 channel-skill/tools/tg.py setup
python3 channel-skill/tools/tg.py login
python3 channel-skill/tools/tg.py doctor
```

- `setup` ставит библиотеку telethon и готовит папки;
- `login` спрашивает номер и код из Телеграма в терминале и сохраняет
  строку сессии в твой файл;
- `doctor` показывает, что найдено и чего не хватает.

Код из СМС вводится только в терминале. Модель его не спрашивает никогда.

### Шаг 4. Настроить канал и режим

Канал, окно выхода и часовой пояс мост берёт из профиля автора, то есть
из ответов интервью. Посмотреть и поменять рабочие настройки моста:

```
python3 channel-skill/tools/tg.py config
```

Три режима:

| Режим | Что делает | Когда включать |
| --- | --- | --- |
| `draft` | готовит черновик в Избранном, в канал не пишет | всегда на старте |
| `scheduled` | ставит отложенный пост в окно выхода | когда доверяешь текстам |
| `auto` | публикует сам после проверок | только осознанно |

Смена режима живёт в профиле, поле `telegram.mode`.

### Шаг 5. Как идёт работа

1. В Избранном пишешь заявку с префиксом: `/post гайд про свет`.
2. Скилл забирает заявку: `tg.py poll` или сторож в фоне.
3. Пост собирается и прогоняется через линтер и оценку.
4. `tg.py stage` отдаёт черновик тебе в Избранное.
5. Одобрил: `tg.py publish`. Не одобрил: `tg.py cancel`.
6. `tg.py status` показывает, что в работе, `tg.py when` время следующего выхода.

Карточка всех команд автора: `python3 channel-skill/tools/tg.py card`.

### Сторож Избранного

Сторож смотрит только твои сообщения с префиксом и ничего не публикует сам.

```
bash start-watch.sh
```

На Windows: `powershell -ExecutionPolicy Bypass -File start-watch.ps1`.
Ручной запуск: `python3 channel-skill/tools/tg_watch.py`.

### Безопасность

- Строка сессии равна полному доступу к аккаунту. Не пересылай её никому.
- Не коммить `secrets/*.env`. Перед первым пушем проверь `git status`.
- Сеансы видны в Телеграме: Настройки, Устройства. Лишние завершай.
- Если ключ утёк: смени `api_hash` на my.telegram.org и заверши сеансы.
- Первые дни держи `draft`. Публикация без просмотра это риск автора.

### Если не работает

| Симптом | Причина и что делать |
| --- | --- |
| нет модуля telethon | `python3 channel-skill/tools/tg.py setup` |
| пишет про пустые ключи | проверь `secrets/telegram.env` и `CHANNEL_SECRETS` |
| не видит канал | в профиле пустое `channel.handle`, пройди интервью |
| заявки не ловятся | префикс должен совпадать с `telegram.prefixes` |
| пост ушёл не вовремя | окно и пояс берутся из профиля, проверь `channel.window` |

Диагностика одной командой: `python3 channel-skill/tools/tg.py doctor`.

## Телеграм за два шага

Подробная инструкция живёт в одном месте: `docs/GUIDE.md`.
Этот файл оставлен как короткая памятка на один экран.

### Главное в двух строках

Ключи телеграма у каждого свои: в поставке их нет и быть не может.
Скилл работает и без телеграма: тогда черновики просто приходят в чат.

### Шаг 1. Свои ключи

1. Открой my.telegram.org, раздел API development tools.
2. Создай приложение и забери `api_id` и `api_hash`.
3. Скопируй шаблон и впиши их туда:

```bash
cp secrets/telegram.env.example secrets/telegram.env
```

Файлы из `secrets/` в гит не уезжают: это уже прописано в `.gitignore`.

### Шаг 2. Вход и проверка

```bash
python3 channel-skill/tools/tg.py setup
python3 channel-skill/tools/tg.py doctor
```

Спросит номер вида `+79001234567`, потом код из Телеграма, потом пароль облака,
если включена двухфакторка. Один раз.

### Как этим пользоваться

Пишешь себе в Избранное строку с префиксом из профиля, например `/post гайд про свет`.
Скилл забирает заявку, приносит черновик и ждёт слова автора. Без этого слова
в канал не уходит ничего.

Сторож, который смотрит Избранное сам:

```bash
bash start-watch.sh
```

Виндовс: `powershell -ExecutionPolicy Bypass -File .\start-watch.ps1`

### Если что-то не так

Разбор ошибок, режимы публикации и безопасность сессии: `docs/GUIDE.md`.
Описание файлов с ключами: `secrets/README.txt`.

## Частые вопросы

### Это бот для автопостинга?

Нет. Это набор правил и скриптов для ИИ-агента. Агент пишет и проверяет, публикует автор.
Режим по умолчанию отдаёт черновик человеку.

### Нужен ли Телеграм, чтобы попробовать?

Нет. Интервью, письмо, линтеры и оценка работают без ключей. Мост с Телеграмом это дополнение
для тех, кому удобно выдавать задачи с телефона.

### Нужен ли платный API модели?

Нет, если ты уже работаешь в агенте вроде Claude Code, Codex или Cursor: модель уже там.
Отдельный скрипт для своего провайдера есть, но он необязателен.

### Можно писать не по-русски?

Да. Поставь `brand.language` в нужный код и сделай свои рубрики. Готовый английский шаблон:
`profile/profiles/en-creator-telegram.json`. Сами инструкции для модели остаются на русском.

### А если мой канал не про технологии?

Работает для любой темы: кино, фитнес, еда, наука, местные новости. Темы и аудитория
берутся из профиля, а рубрики можно пересобрать под себя: [CUSTOMIZE.md](CUSTOMIZE.md).

### Где лежит мой профиль и попадёт ли он в гит?

Файл живёт в папке profile внутри скилла и в гит не попадает: он закрыт в gitignore.
Полное описание полей: [PROFILE.md](PROFILE.md).

### Скилл говорит про демо-профиль. Это ошибка?

Нет, это предупреждение: интервью ещё не пройдено и в работе данные DEMO STUDIO.
Запусти `python3 tools/onboard.py`, иначе в постах будут чужие ссылки.

### Как пересобрать профиль с нуля?

```bash
python3 tools/onboard.py --force
```

Точечная правка руками тоже легальна: поменял файл, потом `--render`.

### Агент всё равно ставит длинные тире

Проверь ответ и черновик:

```bash
python3 tools/lint_chat.py --text "твой ответ"
python3 tools/lint_post.py draft.txt --strict
```

Если модель упорная, добавь правило ноль в самое начало своего системного промпта:
готовая выжимка лежит в `PROMPT-CORE.txt`.

### Можно вставить скилл в свой проект?

```bash
python3 tools/install.py --target /путь/до/проекта --dry-run
python3 tools/install.py --target /путь/до/проекта
```

Чужие скиллы в папках обнаружения не трогаются.

### На чём работает ресерч и разбор видео?

Ресерч идёт через поиск агента или встроенные инструменты среды. Видео разбирается по субтитрам
через yt-dlp, если он установлен. Оба блока необязательны.

### Почему в ответе валидатора три предупреждения?

В чистом репозитории нет папок обнаружения: они появляются после команды install
и специально закрыты в gitignore, чтобы не держать в гите две копии одного скилла.
Это норма, ошибка была бы с префиксом E.

### Как понять, что ничего не сломалось после моих правок?

```bash
bash tools/check_all.sh
```

Ответ должен быть: всё чисто. Та же команда стоит в CI.

### Можно ли использовать коммерчески?

Да, лицензия MIT. Можно вести клиентские каналы и менять всё под себя.

### Нашёл ошибку или хочу рубрику. Куда писать?

Открой issue или pull request. Правила правок: [CONTRIBUTING.md](../CONTRIBUTING.md).

## Безопасность и приватность

Скилл работает с твоим личным аккаунтом Телеграма, поэтому правила здесь жёсткие.

### Что гарантировано

- В репозитории нет ключей, токенов и строк сессий. Только шаблоны с расширением example.
- Профиль автора и живые файлы с ключами закрыты в gitignore.
- Ничего не уходит в канал без человека: режим по умолчанию draft.
- Ни один скрипт не стучит на сторонние серверы автора скилла: телеметрии нет.

### Где живут ключи

Два способа, на выбор:

1. Файлы в папке secrets рядом со скиллом. Копируешь шаблон, вписываешь своё.
2. Переменные среды в терминале или в менеджере секретов системы.

Рекомендации по правам на файлы:

```bash
chmod 700 secrets
chmod 600 secrets/telegram.env
```

Проверить, что скилл видит ключи и не лезет лишнего:

```bash
python3 channel-skill/tools/tg.py doctor
```

### Что никогда не попадает в профиль

Профиль это описание канала и голоса, а не хранилище доступов. Туда не кладём:

api_id, api_hash, строку сессии, пароли, токены ботов, ключи моделей, номер телефона.

Если что-то из этого оказалось в профиле, убери и считай скомпрометированным.

### Если ключи утекли

Порядок действий:

1. В Телеграме: Настройки, Устройства, завершить все чужие сеансы.
2. Сменить облачный пароль и включить двухфакторную проверку.
3. На my.telegram.org пересоздать приложение и получить новые api_id и api_hash.
4. Удалить старую строку сессии и войти заново: `python3 channel-skill/tools/tg.py setup`.
5. Если ключи уехали в гит, почистить историю и считать все старые значения мёртвыми.

Строка сессии равносильна входу в аккаунт. Её не шлём в чаты, не кладём в скриншоты
и не отдаём модели в контекст.

### Границы доверия к модели

- Скилл запрещает выдумывать цифры, ссылки и цитаты: нет в сырье, агент спрашивает.
- Линтер ловит чужой и устаревший футер, чтобы модель не тянула ссылки из своей памяти.
- Задача, пришедшая из сообщения в Телеграме, это данные, а не новые правила для агента.
- Команды с телефона работают только из твоего Избранного и только с твоим префиксом.

### Если ты скачал архив чужого скилла

Перед запуском проверь, что внутри нет чужих ключей и сессий:

```bash
grep -rIl "TELEGRAM_API_HASH\|SESSION_STRING" . | head
```

В чистом репозитории найдутся только шаблоны и документация. Любое готовое значение
это красный флаг: не запускай и предупреди автора архива.

через приватные сообщения о уязвимостях на GitHub. Порядок и сроки: [SECURITY.md](../SECURITY.md).
