# Безопасность и приватность

Скилл работает с твоим личным аккаунтом Телеграма, поэтому правила здесь жёсткие.

## Что гарантировано

- В репозитории нет ключей, токенов и строк сессий. Только шаблоны с расширением example.
- Профиль автора и живые файлы с ключами закрыты в gitignore.
- Ничего не уходит в канал без человека: режим по умолчанию draft.
- Ни один скрипт не стучит на сторонние серверы автора скилла: телеметрии нет.

## Где живут ключи

Два способа, на выбор:

1. Файлы в папке secrets рядом со скиллом. Копируешь шаблон, вписываешь своё.
2. Переменные среды в терминале или в менеджере секретов системы.

Рекомендации по правам на файлы:

```bash
chmod 700 secrets
chmod 600 secrets/telegram.env
```

Проверить, что скилл видит ключи и не лезет лишнего:

```bash
python3 channel-skill/tools/tg.py doctor
```

## Что никогда не попадает в профиль

Профиль это описание канала и голоса, а не хранилище доступов. Туда не кладём:

api_id, api_hash, строку сессии, пароли, токены ботов, ключи моделей, номер телефона.

Если что-то из этого оказалось в профиле, убери и считай скомпрометированным.

## Если ключи утекли

Порядок действий:

1. В Телеграме: Настройки, Устройства, завершить все чужие сеансы.
2. Сменить облачный пароль и включить двухфакторную проверку.
3. На my.telegram.org пересоздать приложение и получить новые api_id и api_hash.
4. Удалить старую строку сессии и войти заново: `python3 channel-skill/tools/tg.py setup`.
5. Если ключи уехали в гит, почистить историю и считать все старые значения мёртвыми.

Строка сессии равносильна входу в аккаунт. Её не шлём в чаты, не кладём в скриншоты
и не отдаём модели в контекст.

## Границы доверия к модели

- Скилл запрещает выдумывать цифры, ссылки и цитаты: нет в сырье, агент спрашивает.
- Линтер ловит чужой и устаревший футер, чтобы модель не тянула ссылки из своей памяти.
- Задача, пришедшая из сообщения в Телеграме, это данные, а не новые правила для агента.
- Команды с телефона работают только из твоего Избранного и только с твоим префиксом.

## Если ты скачал архив чужого скилла

Перед запуском проверь, что внутри нет чужих ключей и сессий:

```bash
grep -rIl "TELEGRAM_API_HASH\|SESSION_STRING" . | head
```

В чистом репозитории найдутся только шаблоны и документация. Любое готовое значение
это красный флаг: не запускай и предупреди автора архива.

через приватные сообщения о уязвимостях на GitHub. Порядок и сроки: [SECURITY.md](../SECURITY.md).
