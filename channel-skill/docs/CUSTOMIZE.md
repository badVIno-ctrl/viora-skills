# Настройка под свой канал

Всё, что касается твоего канала, меняется в профиле. Код править не надо.
После любой правки прогони две команды:

```bash
cd channel-skill
python3 tools/profile.py --check
python3 tools/onboard.py --render
```

Первая проверяет профиль, вторая разносит новые данные по текстам скилла
и пересобирает промпты.

## Свои рубрики

В скилле есть готовый набор рубрик с каркасами и коридорами длины. В профиле ты его правишь
точечно, а не переписываешь целиком:

```json
{
  "rubrics": {
    "гайд": { "min": 700, "max": 1500 },
    "реклама": null,
    "опрос": { "points": [1, 3] }
  }
}
```

- объект с полями перекрывает только указанные поля;
- `null` или слово нет выключает рубрику совсем;
- хотя бы одна рубрика должна остаться, иначе проверка ругается.

Посмотреть, что получилось:

```bash
python3 tools/profile.py --show
python3 tools/channel.py route "нужен пост про новый инструмент"
```

## Свой голос

Блок voice в профиле:

```json
{
  "voice": {
    "greeting_max_words": 4,
    "extra_banned": ["друзья", "коллеги", "в современном мире"],
    "extra_lexicon": ["сборка", "пресет", "таймлайн"]
  }
}
```

- `greeting_max_words` ограничивает длину первой строки поста;
- `extra_banned` добавляет свои стоп-слова к общему списку штампов;
- `extra_lexicon` это твои слова, которые скилл старается использовать.

Проверка приветствия на повтор:

```bash
python3 tools/memory.py check-greeting "первая строка поста"
```

## Свой футер

По умолчанию футер собирается из списка links в том же порядке. Если хочешь свою строку
знак в знак, задай `footer.template`. Проверить результат:

```bash
python3 tools/profile.py --footer
```

Старые подвалы из архивных постов перечисли в `footer.legacy_labels`: линтер будет ловить их
как ошибку, если модель вспомнит старый вариант.

## Второй бренд или мемный подканал

```json
{
  "second_brand": {
    "enabled": true,
    "name": "МЕМ ОТДЕЛ",
    "tag": "второй",
    "min": 40,
    "max": 220,
    "footer": false
  }
}
```

Правила голоса и шаблоны коротких шуток лежат в `reference/second-brand.md`.
Когда `enabled` выключен, рубрика исчезает из маршрутов и не мешает.

## Свои цифры для оценки

```json
{
  "metrics": { "subscribers": 1200, "reach": [400, 900], "reactions": [3, 12] }
}
```

Оценка сравнивает черновик с твоими реальными вилками, а не со средним по рынку.
Заниженные цифры делают оценку бессмысленной, поэтому бери данные из статистики канала.

## Другой язык

Поставь `brand.language` в en, es или другой код и сделай свои рубрики с латинскими именами,
а русские отключи через `null`. Готовый пример лежит в `profile/profiles/en-creator-telegram.json`.
Справочники остаются на русском: это инструкции для модели, не для читателя.

## Свои правила и свои файлы

1. Добавь файл в папку reference и опиши в нём один сюжет.
2. Пропиши строку в `ROUTER.md`, чтобы агент знал, когда его читать.
3. Если правило важно всегда, заверни его в блок CORE и пересобери промпты:

```bash
python3 tools/build_prompt.py
python3 tools/build_prompt.py --check
```

4. Проверь целостность скилла и эталоны:

```bash
python3 tools/validate_skill.py --root ..
python3 tools/run_evals.py
```

Новые проверки поведения добавляются в `evals/cases.json`.

## Чего лучше не делать

- Не вписывать имя канала и ссылки в код скриптов: сломается при обновлении.
- Не править `PROMPT-CORE.txt` и `PROMPT-FULL.txt` руками: они собираются из источников.
- Не добавлять длинные тире ни в профиль, ни в свои файлы: проверка упадёт.
- Не хранить ключи в профиле: им место в папке secrets или в переменных среды.
