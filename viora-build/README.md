# Viora Build

*Оркестратор Viora Studio. Собирает проект целиком чужими руками: Design Skills, Code Protocol, Aegis.*

## Зачем отдельный скилл

Три основных пакета умеют каждый своё, но ни один из них не знает порядка работ. Если попросить
агента «собери сайт», он начнёт вёрстку без токенов, вспомнит про безопасность в конце и проверит
всё один раз перед сдачей. Viora Build задаёт порядок и условия перехода между фазами — и больше
ничего.

**Главное свойство: в нём нет ни одного собственного правила** про дизайн, код или безопасность.
Поэтому он не расходится с остальными пакетами при их обновлении и не занимает контекст.

## Когда включать

| Задача | Что использовать |
|---|---|
| Сайт / приложение с нуля | **viora-build**, фазы `P0`–`P7` |
| Полный редизайн или «довести до релиза» | **viora-build**, старт с `P1` |
| Одна фича, один баг, рефакторинг | `viora-code-protocol` напрямую |
| Одна правка по визуалу | `viora-design-skills` напрямую |
| Аудит или харденинг | `viora-aegis` напрямую |

Пайплайн на мелкой задаче — это потеря времени и контекста. Скилл сам отправит вас к дочернему
пакету, если задача маленькая.

## Фазы

| Фаза | Что происходит | Кому делегирует | Чем закрывается |
|---|---|---|---|
| `P0` | Бриф, список поверхностей, стек, критерии готовности | — | `.viora/BUILD.md` |
| `P1` | Направление и токены | design `G0`–`G3` | `DESIGN.md` + `tokens.css` |
| `P2` | Каркас: маршруты, одна точка монтирования, план файлов | protocol `FEATURE` | сборка проходит |
| `P3` | Поверхности по одной за итерацию | protocol `UI` + design `G4` | ворота на каждой итерации |
| `P4` | Состояния, a11y, подписной момент, вычитание | design `G5`–`G6` | `check.mjs` без ошибок |
| `P5` | Модель угроз, аудит, харденинг, фиксы | aegis `AUDIT`/`HARDEN` | `SECURITY_REPORT.md` |
| `P6` | Общий гейт по всему проекту | все три | таблица доказательств |
| `P7` | Отчёт и список задач на стороне заказчика | — | финальный отчёт |

Две вещи, которые легко пропустить:

1. **Безопасность не только в `P5`.** Режим `GUARD` из Aegis работает молча с `P2`. Фаза `P5` — это
   аудит, а не первая мысль о безопасности.
2. **Состояние живёт в файлах.** `.viora/BUILD.md` + `DESIGN.md` + отчёты. Сессия может упасть и
   продолжиться с той же фазы — именно это делает длинные сборки возможными на слабых моделях.

## Установка

Положите рядом с тремя остальными пакетами — в ту же папку скиллов:

```
.claude/skills/
├── viora-build/
├── viora-design-skills/
├── viora-code-protocol/
└── viora-aegis/
```

Скилл работает и без части пакетов: чего нет — о том скажет вслух и перейдёт на запасной вариант
из раздела 8 `SKILL.md` (свои правила вместо отсутствующего пакета он не выдумывает).

## Как пользоваться

```
Собери лендинг для студии автоматизации. Работай по Viora Build.
```

Правильное поведение: агент объявляет фазу одной строкой (`P1 direction: ...`), задаёт один блок
вопросов на `P0`, не начинает вёрстку без `tokens.css` и не строит шесть секций за один проход.
Если он сразу пишет HTML — скилл не загружен.

Полезные фразы:

- «Продолжай сборку с текущей фазы» — агент прочитает `.viora/BUILD.md` и продолжит с нужного места.
- «Только `P5` и `P6`» — безопасность и общий гейт по готовому проекту.
- «Не переходи к `P3`, пока не покажешь план файлов» — жёсткий контроль на большом проекте.

## Общий гейт

Одна команда вместо шести — запускает скрипты всех найденных пакетов и печатает одну таблицу:

```bash
bash scripts/pipeline_check.sh .
bash scripts/pipeline_check.sh . --only design,security
VIORA_SKILLS_DIR=~/.claude/skills bash scripts/pipeline_check.sh /путь/к/проекту
```

Скрипт ничего не знает о правилах: он только вызывает чужие проверки, исходники не меняет, логи
кладёт в `.viora/build/`. Код возврата `1` — хотя бы один гейт упал.

## Что внутри

```
SKILL.md                     контракт, роутер, карта фаз, передача между фазами, формат отчёта
README.md                    этот файл
templates/BUILD.template.md  шаблон файла состояния .viora/BUILD.md
scripts/pipeline_check.sh    общий гейт по трём пакетам
```

Ни одного справочника — и это намеренно. Вся глубина живёт в трёх дочерних пакетах.
